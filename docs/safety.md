# Safety pass (private)

Everything that can damage a printer, waste a print or hurt someone, checked against what OrcaSlicer does (at commit `7d42ad17a4`, read as a behavior reference only) and what SlicerX does on 2026-09-30. Each row has the check, Orca's behavior, ours today and the gap. Priorities: P0 fix before any real print or public release, P1 soon after, P2 when the related feature lands.

One finding shapes most rows: the safety logic lives in three places that do not talk to each other. `packages/settings` (`validate.rs`, `plan.rs`) judges settings and material choices. `packages/core` slices and only warns about the plate being outside the bed. `packages/connect` gates printer actions with approvals. Nothing checks the emitted G-code against the printer before it leaves the machine, and `validate_gcode` in `packages/core/src/validate.rs` (bed, height, Z never down, retraction depth) runs only in tests and benches. The main recommendation is a single preflight that runs on every path that produces or sends G-code (app export, MCP, CLI, cloud slicer, phone) and returns errors that block and warnings that need a person's yes.

## Placement and volume

| Check | What Orca does | What SlicerX does today | Gap | Priority |
| --- | --- | --- | --- | --- |
| Object outside the printable area | Tests every instance against the build volume, marks it, and blocks slicing or export until fixed. After slicing it also tests the generated toolpaths (skirt, brim, supports, wipe tower) against the plate area and height. | Core adds an `outside_bed` warning from the bounding box of the parts against the bounding rectangle of `printable_area`. The app has `fitsBed` for the plate tool. Warnings never block. | Circular and custom beds are treated as rectangles, so a corner of a round bed passes. No toolpath-level test on emitted output. Run the G-code validator on every emit and make an outside-bed result an error that export must acknowledge. | P0 |
| Object above the maximum height | Error naming the object, including when shrinkage compensation or the last layer pushes it over. | Warning only, plus a Z limit in the test-only validator. | Make it an error. Include z-hop, raft and first-layer offset in the height. | P0 |
| Object below the bed | Cut off or flagged. | Warning, part cut at Z 0. | None beyond the blocking policy above. | P2 |
| Excluded bed areas (purge and cutter zones, `bed_exclude_area`) | Placement and arrange avoid them, toolpaths are checked against them, and sequential printing reports objects "too close to the exclusion area". | The key is in the schema; the core, arrange and viewport ignore it. | Read the key, draw the zones, keep arrange out of them, include them in the toolpath test. Several Bambu, Prusa and Creality profiles define real purge or cutter zones a nozzle must not enter. | P0 |
| Per-extruder printable area and height | Dual-extruder machines get their own area and height per extruder. | Not read. | Needed with multi-extruder support. | P1 |
| Sequential (by object) collision checks | Compares each object's footprint grown by `extruder_clearance_radius` (and `extruder_clearance_max_radius`) against the others, uses `extruder_clearance_height_to_rod` and `_to_lid` for the gantry when objects overlap on Y, relaxes the distance when all objects are short, and reports the colliding pairs. Also disallows skirt and prime tower combinations that break by-object printing. | Built in the core (`src/sequence.rs`, Bambu Studio's rule): hull distance against `extruder_clearance_radius`, the rod height where the gantry passes over an earlier object, the lid height elsewhere, the short object and per-object skirt cases. A refused plate stops the slice with `Error::Clearance`; MCP returns `sequence_clearance`. Not checked yet: exclusion areas. | Build the check with the feature, not after it: clearance radius, gantry height, exclusion areas, and a hard stop on the last-printed object's height against the rod. A print that sweeps the gantry through an earlier object is the most damaging slicing mistake short of a wrong Z. | P0 |
| Overlapping or too-close objects (by layer) | Arrange keeps a spacing; overlap is allowed and merged, no hard error. | Arrange default gap 6 mm; no overlap detection. | Warn when instances intersect, since merged geometry may be accidental. | P2 |
| Wipe tower placement and clearance | Tower must sit inside the bed, arrange avoids it, and a clearance check compares the rod height against the tower (compacted towers). | No tower yet. | Add with the tower: bed bounds, object overlap, exclusion zones, rod height. | P0 (with tower) |
| Toolpath conflicts between objects | Scans generated paths of different objects for collisions and names the layer and pair. | None. | Needed for by-object and tower prints. | P1 |
| Moves outside the bed in the final G-code | Post-slice test of extrusion and travel against area and height. | `validate_gcode` (X and Y bounds, Z bound, Z never decreases, absolute XYZ, relative E) exists but is never run outside tests. | Run it in `emit_gcode` for every flavor and surface its errors. | P0 |

## Temperature and materials

| Check | What Orca does | What SlicerX does today | Gap | Priority |
| --- | --- | --- | --- | --- |
| Nozzle temperature against the hotend limit | No hard stop; the filament's recommended range produces a warning dialog. | `packages/settings` warns outside the filament's documented range (`temp_outside_range`) and the material planner clamps to `hotendMaxTemp` from the printer catalog. The core writes any `M104`/`M109` value. | Cap at emission with an error above the printer's limit. Catalog limits are empty for some printers, so unknown means ask, never assume. Add a PTFE-lined hotend rule: block or double-confirm above about 240 to 260 degrees Celsius, since PTFE degrades and off-gasses (a real hazard to people and pet birds). Orca has no such rule. | P0 |
| Bed temperature against the bed limit and plate type | Per plate type temperatures; an error names a plate that does not support the chosen filament. | One bed temperature. Plate type keys (cool, engineering, high temp, textured, supertack) are unread. The planner clamps to the printer's `bedMaxTemp`. | Read plate type and its temperatures; refuse a plate type the filament cannot use; cap the bed at the printer limit at emission. | P0 |
| Abrasive filament needs a hardened nozzle | Compares the filament's `required_nozzle_HRC` with the printer's `nozzle_hrc` and warns to fit a hardened nozzle or change filament. | The material planner (`plan.rs`) stops a plan that puts an abrasive material on a soft nozzle, and mimir repeats it in its warnings. The core, export and send paths do not check; the schema keys are ignored. | Enforce at slice, export and send, for every entry point and for imported profiles, using the fitted nozzle type (brass, stainless, hardened steel, tungsten carbide, ruby) with "unknown" treated as "ask". Materials to cover: carbon or glass filled, glow in the dark, metal filled, some wood and stone fills. | P0 |
| Chamber temperature | Warns when the requested chamber temperature exceeds the material's safe limit (softening and clogs). Emits chamber control only on printers that support it. | The knowledge base holds chamber ranges per material. No `M141` or `M191` output and no check. | Cap at the printer's chamber limit and the material's softening point; never wait forever for a chamber (timeout, then continue or stop). | P1 |
| Hot bed in an enclosure with low-temperature filament | Warns that a high bed temperature in a closed printer can clog the nozzle for the filament and says to open the door. | Knowledge base has enclosure guidance for mimir; no slice-time check. | Add the rule to the settings validator (enclosed printer, PLA and PVA class, bed above a threshold). | P1 |
| Soft materials (TPU 85A, 90A) and multi-material units | Pre-print checker warns TPU is too soft for automatic flow calibration and for the AMS, honors a per-filament "printable through AMS or external spool" flag, and says which spool the file expects. | `filament_printable` is in the schema, unread. No AMS mapping yet. | Add with slot mapping. Also block flexible filament through a Bowden path with the wrong retraction. | P1 |
| Mixed filament temperature compatibility | Errors when the recommended temperature ranges of filaments in one print do not overlap, with a preference to override. | None. | Add with multi-material: each filament's temperature must sit inside the others' recommended range. | P1 |
| Soluble support and interface materials | Carries `filament_soluble` and `filament_is_support` flags; support and interface filaments can be assigned. | Flags in the schema, unread. Support filament assignment is missing. | Rules to add with the feature: soluble filament only for support features; interface of two or more layers; a purge or tower for the tool change; temperature compatibility with the model material (PVA degrades near PETG temperatures); dry storage reminder. | P1 |
| Different nozzle diameters with a tower | Warns that mixing nozzle and filament diameters with a tower is experimental. | None. | Add with multi-extruder. | P2 |
| Filament and nozzle diameter sanity | Rejects zero or negative diameters and flow ratios out of range. | `packages/settings` checks types and ranges for every key. The core has its own parse errors. | Confirm the core rejects zero and negative diameters, flow ratios and temperatures when called directly (MCP, CLI, cloud). | P1 |

## Extrusion, motion and layer limits

| Check | What Orca does | What SlicerX does today | Gap | Priority |
| --- | --- | --- | --- | --- |
| Layer height against nozzle diameter | Error: layer height, and initial layer height, cannot exceed the nozzle diameter. Minimum and maximum layer height come from the printer profile. | `packages/settings` has `layer_above_nozzle`, `first_layer_above_nozzle`, `layer_above_max` and `layer_below_min`. The core does not check. Smart Layer plans are bounded (0.04 to 0.8 mm) and intersected with the material window. | Enforce in the core: any caller that bypasses the settings package (CLI, FFI, cloud, MCP) can slice a 1.2 mm layer on a 0.4 mm nozzle today. | P0 |
| Line width against nozzle and layer | Errors for too small or too large line widths (including bridge line width above the nozzle diameter). | `line_width_range` in settings; the core accepts any width and treats 0 as automatic. | Same: enforce in the core. | P0 |
| Maximum volumetric speed | Clamps speeds so flow stays under `filament_max_volumetric_speed`, per feature, in G-code generation. | Settings warns (`flow_limit`) when speed times width times height exceeds the limit. The core does not cap, so fast profiles over-extrude past the hotend's melt rate. | Implement the cap in path planning (also drives the time estimate). This is the most common cause of grinding and clogged nozzles from a bad profile. | P0 |
| Machine limits (speed, acceleration, jerk, junction deviation) | Emits the limits when asked and warns in the UI about values above them. | `accel_over_machine` warning in settings and planner clamps to catalog limits. The core neither emits limits nor clamps speeds. | Clamp at planning, emit `M201`, `M203`, `M204`, `M205` or the Klipper equivalent when the profile asks, and make the estimate use them. | P0 |
| First layer and Z offset sanity | Rejects a zero initial layer height and resets to a default; resets elephant foot values that are too large; no bounds on `z_offset`. | `first_layer_above_nozzle` in settings. `z_offset` is not read by the core. | When `z_offset` is implemented, bound it (warn beyond about 0.3 mm, refuse a value that puts the first layer below the bed) and never let a per-object or height range override change it. | P1 |
| Retraction sanity | Ranges in the config definitions. | Test-only validator rejects retraction deeper than a limit. | Cap retraction length by drive type (direct or Bowden) at emission. | P2 |
| Spiral vase restrictions | Offers to fix the conflict: one wall, no support, zero top layers, zero infill, traditional timelapse; requires by-object for several objects; refuses multi-material objects. | Settings flags `spiral_walls`, `spiral_infill` and `spiral_with_support`. No spiral mode in the core. | Add the top-layer, multi-object and multi-material rules when spiral mode is built. | P1 |
| Configuration conflicts with automatic fixes | A long list of dialogs: ironing spacing floor, elephant foot too large, support Z distance rounded to the layer height, fuzzy skin needs Arachne, seam slope height below layer height, infill lock depth, organic tree tip and branch sizes, pattern unsupported by tree supports, hollow and lightning fallbacks, G92 E0 rules with relative extrusion, tower needs relative E and specific flavors, ooze prevention only with a tower, same layer height for all objects under a tower. | 27 rule codes in `packages/settings/src/validate.rs` (range, enum, temperature, flow, layer and line limits, Smart Layer bounds, spiral, arc fitting with slope, firmware retraction). | Port the rest as each feature lands; give each a code, keys, message and a suggested fix, never applied silently (the existing pattern). | P1 |
| Extrusion role and E reset consistency in custom G-code | Errors when layer change G-code resets E incorrectly for the extruder addressing mode. | Not applicable: no custom G-code yet. | Add when templates land (see G-code macros). | P1 |
| Nothing to print | "No extrusions under current settings." | `nothing_to_print` in settings, `EmptyPlate` in the core. | None. | P2 |
| Open edges, floating regions, thin walls | Notifications from mesh checks and support analysis. | `open_edges`, `floating_region` and `thin_wall` warning codes; open edges is emitted. | Emit floating region and thin wall. | P1 |

## G-code and macros

| Check | What Orca does | What SlicerX does today | Gap | Priority |
| --- | --- | --- | --- | --- |
| Custom G-code (start, end, layer change, tool change, pause, filament) is safe to run | Copies the text into the file. Nothing stops `M104 S999`, a `M109` or `M190` with no target, `M84` mid-print, `M500` (writes EEPROM), `SAVE_CONFIG` (rewrites the Klipper config and restarts), `FIRMWARE_RESTART`, shell-command extensions, heaters left on. Anyone who opens a shared project or preset runs whatever is in it. | The core emits only its own fixed start and end. Profile G-code fields are not used yet, which is why nothing is exposed. | Before templates ship, add a G-code linter used on every source of G-code text (profiles, 3MF projects, library files, MCP, mimir): bound every heater and fan command to the printer's limits, require a target on every wait, deny a list of persistent or destructive commands (EEPROM writes, config saves, restarts, firmware updates, shell hooks, PID and probe offset changes), require heaters off in the end sequence, and require the linter's pass or a person's explicit approval of the diff. Text from imported files is untrusted by default. | P0 |
| Post-processing scripts | Runs any executable named in the config's `post_process`, including one that arrived inside a project or shared preset. | No hook yet (planned under `docs/core-features.md`). | Read `post_process` only from the local user's own settings, never from an imported file, project, library item or MCP call; no shell, explicit allow list of paths; never in the browser, cloud slicer or WASM build. Make the settings importer drop the key today and add a test. | P0 |
| Heaters off after the print, abort and error | The profile's end G-code is expected to do it; nothing verifies. | End sequence sets `M104 S0`, `M140 S0`, `M107`, `M84`. | Verify in the linter for custom end G-code. Cancel through `packages/connect` should also send heater off where the driver allows it. | P1 |
| Wrong relative or absolute mode left set | Validated only for E reset rules. | Test-only validator checks absolute XYZ and relative E. | Include in the preflight on emitted files. | P1 |
| File sliced for a different printer | No check outside the Bambu send dialog (nozzle information, firmware, storage, busy state, unmapped filaments). | Nothing at send time. | Write printer id, model, nozzle diameter, bed size, flavor and material into the header, and compare with what the printer reports (Moonraker and Bambu report a lot) before upload and again before start. A 300 mm file on a 180 mm printer crashes the head into the frame. | P0 |
| Resume from layer: Z safety | Not a slicer feature; only firmware power loss recovery. | `resume_header` heats, runs `G28 X Y` and then either trusts the printer's Z or declares it with `G92 Z` (only `mode: "declare"`, finite and 0 or more). A `manual_step` warning says the nozzle must be moved by hand first. Bed temperature comes from `hot_plate_temp`, nozzle temperature from slot 1. | (1) Homing X and Y with the nozzle low on a failed print can drag the nozzle through the part; lift Z relative before any XY homing and refuse to run when Z is unknown and not declared. (2) Cap the declared Z at the printable height and at the sliced part height, and echo the number in the approval so the person confirms what they measured; an overstated Z sends the nozzle down into the part. (3) Run the whole resumed file through the toolpath check with the declared Z as the floor. (4) Use first layer and per-filament temperatures, and every slot's temperature for multi-tool. (5) Never approve a resume from the phone alone (see approvals). | P0 |
| Purge before printing after a long idle or failed print | Profile start G-code decides. | Resume path draws no purge line by design. | Offer an optional purge line for a resume; warn that a dry nozzle can be clogged. | P2 |

## Approvals and printer actions

| Check | What Orca does | What SlicerX does today | Gap | Priority |
| --- | --- | --- | --- | --- |
| Gate for every printer side effect | None; the user presses send. | `packages/connect/src/gate.rs`: single-use approval tokens bound to the action, the printer and a hash of the parameters (upload, start, pause, resume, cancel, raw G-code, plugin call). `packages/pilot/permit` broker: five minute lifetime, checked on every side effect. MCP: a permission policy file the model cannot edit, Allow, Ask first or Off per class, defaults slice allow, queue, start, profile, printer config and share ask, buy off. mimir evals report zero side effects without a token. | Solid base. Gaps below. | done |
| What the person sees when approving | Not applicable. | Approval cards exist; contents not audited here. | The card must show printer name, file name and SHA-256, layers and time, nozzle, bed and chamber temperatures, material against what is loaded, and for a resume the declared Z. The token should bind to the file hash so a swapped file cannot ride an old approval (confirm that `start` hashes content, not just a name). | P0 |
| Raw G-code action | Not applicable. | A token authorizes any single line through `send_gcode`. There is no permission class named for it; it maps onto existing classes. | Run the G-code linter inside the connect layer regardless of approval, give raw G-code its own always-ask class, and never allow it from a model without the person seeing the exact text. | P0 |
| Pause, resume and cancel | Not applicable. | Gated actions. Policy classes group them under start or printer config. | Cancel and pause should be cheap to approve, start and raw G-code expensive. Give them separate classes. | P1 |
| Bed clear and supervised start | Not applicable. | No check. | Ask "is the bed clear" on every start. For a remote start (phone, mimir, MCP) warn that nobody may be present, and let the person set a rule such as no unattended start above a temperature or with a heated chamber. Product decision. Done for remote access (2026-10-02): over the relay a phone approves only pause and cancel cards; starts (agent, queued, scheduled), resume, raw G-code and adjustments are approved in the app or at the printer, and a bed answer sent over the relay is ignored. | P1 |
| Phone approvals | Not applicable. | Design: a plain tap approves, Face ID is an optional setting, off by default. | Keep the same approval card as desktop, bound to the same token. Raw G-code, a resume and a first print on a new printer should require the desktop or Face ID whatever the setting. Open product question. | P1 |
| Model context and hostile input | Not applicable. | mimir evals include hostile file names, model metadata and printer replies. | Keep in the eval set; add G-code comments and profile notes as injection surfaces. | P2 |

## Software and supply chain

| Check | What Orca does | What SlicerX does today | Gap | Priority |
| --- | --- | --- | --- | --- |
| Library upload scanning | None; Orca has no upload path. | `editions/slicerx/packages/cloud/scan`: size caps, SHA-256 blocklist, ClamAV through clamd (unavailable means not approved), type from content, archive audit before inflating (entry counts, sizes, compression ratio, overlaps, encryption, duplicate names, path escapes, symlinks, odd compression, trailing data, executable and script names and signatures), embedded G-code and settings stripped, XML hardened, mesh parsed, archive rebuilt. Hostile fixtures cover zip bombs, traversal, EICAR and more. | Strong. Remaining: only the store validator (`validateUpload`) runs client side, which checks name, size and format only, so the scan must be the gate everywhere. | P2 |
| Opening an untrusted 3MF or STL locally | Trusts the file; a bad archive can exhaust memory. | `core/src/threemf.rs` and `geom/src/import/container.rs` cap a single entry at 1 GiB and nesting at 16. No total size, entry count, ratio or name checks; the WASM build would run out of memory first. | Apply the scan crate's archive rules (own implementation under the MPL license, since the scan crate is AGPL) to every local open: total and per-entry caps well below 1 GiB in the browser, entry count, ratio. Add mesh caps (triangle and vertex counts) and fuzz tests for STL, OBJ, AMF and 3MF. | P0 |
| Settings and G-code carried by a project 3MF | Loads them all, including macros and `post_process`. | `project_metadata` reads settings entries; the importer accepts known keys. | Mark keys that came from a file as untrusted; strip `post_process`; run the G-code linter; show what changed against the user's profile and require a yes for G-code fields. | P0 |
| Credentials never logged or exported | Printer host passwords and API keys sit in preset files and can travel in exported bundles. | `packages/connect/src/secrets.rs` keeps secrets in the Keychain with a redaction test; `ApprovalToken` hides its token in `Debug`; mimir session logs redact `sk-` keys and bearer tokens. | The schema holds `printhost_password`, `printhost_apikey` and `printhost_user`: make import move them into the Keychain and strip them from every export, 3MF, log, MCP tool result and mimir context. Redact by key name (password, apikey, token, secret, access code) and by URL user info, not only by token shape. Add an end-to-end test that plants sentinel secrets and greps every output and log. Check the Bambu LAN access code path in `ftps.rs` and the MQTT driver for logging. | P0 |
| MCP and mimir cannot loosen their own permissions | Not applicable. | The policy file is read once at startup and no tool writes it. | Keep; add a test that no tool schema touches the policy path. | P2 |
| Cloud slicing inputs | Not applicable. | Service slices uploaded plates. | Put hard limits on time, memory and mesh size, and run the same archive audit before slicing. | P1 |
| Dependency and license hygiene | Not applicable. | `deny.toml` exists, license audit doc exists. | Keep `cargo deny` in the release gate. | P2 |

## Suggested order of work

1. Preflight module shared by every G-code path: bed and height (real bed shapes, exclusion zones), temperature and machine limits, nozzle hardness, layer and line limits, printer identity match. Runs `validate_gcode` and returns errors and warnings.  Checks live in the core, rule data in the settings package, the send-time match in the connect package.
2. Volumetric speed cap and machine limit clamping in path planning.
3. G-code linter and the rule that imported text is untrusted, before templates and `post_process` are implemented. Importer change today: drop `post_process`, divert host credentials.
4. Resume path fixes (lift before XY homing, bounded declared Z, hash-bound approval).
5. Sequential printing check shipped together with by-object printing.
6. Archive and mesh caps for local file opens, with fuzz tests.
7. Approval card contents, raw G-code class, bed-clear prompt.
