# Safety checks

This page lists what SlicerX checks before a file leaves the slicer and while it drives a printer: where the plate sits, temperatures and materials, extrusion and motion limits, custom G-code, approvals for printer actions, raw G-code lines, and files that come from somewhere else. Each entry says what SlicerX does and names the file that does it.

A check that refuses or blocks stops the slice, the file or the action and says why. A check that warns lets it go on and shows the warning so the person can decide.

The engine runs its checks for every entry point (the app, the command line, the MCP server and the cloud slicer): settings are checked and pulled into range before slicing (`clamp_config` in `packages/core/src/preflight.rs`), and every toolpath is checked again when the G-code is written (`packages/core/src/gcode.rs`). The app adds a send preflight that compares the sliced file with the printer as it is right now. The hub (`packages/connect`) checks every printer action against an approval and against the printer's state.

## Placement and volume

| Check | What SlicerX does | Code |
| --- | --- | --- |
| Toolpaths outside the printable area | When the G-code is written, every extrusion path is tested against the printer's real bed outline, round and custom beds included. A path off the bed refuses the file with the layer, the position and the object to move. Skirts on Bambu Lab printers may run up to 1.9 mm past the edge. | `packages/core/src/preflight.rs` (`check_toolpaths`), called from `packages/core/src/gcode.rs` |
| Print taller than the printer | A layer whose top, with z-hop, is above the printable height refuses the file and names the first layer that gets there. | `packages/core/src/preflight.rs` |
| Plate laid out for another bed | Before a send, the plate's bounds are compared with the printer catalog's build volume for the model the printer reports. A plate past the bed or over the height blocks the send; a plate sliced for a bed of another size warns. When the catalog does not know the printer, the card says the bed was not checked. | `packages/app/src/plate/preflight.ts` |
| Part below the bed | Warns, and the part is cut off at Z 0. | `packages/core/src/session.rs` |
| Excluded bed areas | Zones from `bed_exclude_area` and the nozzle wrap check corner (`head_wrap_detect_zone`) are read from the printer profile. Arrange keeps objects out of them. A path that enters an excluded area refuses the file; in the nozzle wrap check corner only the skirt is refused, by this check. An object may print in the corner, and the printer then skips its wrap check (`in_head_wrap_detect_zone`). | `packages/core/src/preflight.rs`, `packages/core/src/arrange.rs`, `packages/core/src/collide/plate.rs` |
| Extruder reach on two-extruder printers | Each filament's paths must stay inside its extruder's printable area (`extruder_printable_area`). A path outside it refuses the file and says to map the filament to the other extruder or move the part. | `packages/core/src/preflight.rs` |
| Duplication and mirror modes | When the start G-code puts a dual-head printer in duplication or mirror mode (`M605` or `SET_DUAL_CARRIAGE`), the copy the second head prints must also land on the bed and outside excluded areas, and in mirror mode the heads must not cross. Otherwise the file is refused. | `packages/core/src/preflight.rs` (`check_copy`) |
| Print by object: head, gantry and tool changer | Every move of a by-object print, and every tool change, is tested against what is already printed at that moment, using the printer's own head shape, gantry rod height and lid height. The command line and the MCP server refuse a plate with a hit unless the caller asks to slice anyway (`--allow-collisions`, `allow_collisions`); the app's send preflight blocks a hit. A plate inside the profile's clearance radius whose head shape clears is reported as a close call, which warns. | `packages/core/src/collide/mod.rs`, `packages/core/cli/src/main.rs`, `packages/app/src/plate/preflight.ts` |
| Paths of different objects crossing | Paths of two objects, or of an object and the prime tower, that cross on the same layer are found layer by layer and reported per pair, with the same refusal and override as above. | `packages/core/src/collide/plate.rs` |
| Overlapping objects | Arrange keeps a gap between objects (6 mm by default). Objects that still overlap warn, naming the pair and the layers; the overlap prints once. | `packages/core/src/arrange.rs`, `packages/core/src/api.rs` |
| Prime tower placement | The tower's paths go through the same toolpath check as the objects, so a tower off the bed refuses the file and says to move the tower. | `packages/core/src/preflight.rs` |

## Temperature and materials

| Check | What SlicerX does | Code |
| --- | --- | --- |
| Nozzle temperature against the hotend limit | Nozzle temperatures above the printer's hotend limit are lowered to the limit, with a warning. When the limit is unknown, 350 degrees C is used. A negative or non-number temperature refuses the slice. The settings checker also warns about a temperature outside the filament's range. | `packages/core/src/preflight.rs`, `packages/core/src/gcode_lint.rs`, `packages/settings/src/validate.rs` |
| PTFE-lined hotends | On a printer whose hotend is known to be PTFE lined, a nozzle temperature above 260 degrees C refuses the slice and one above 240 degrees C warns: the liner breaks down and gives off fumes that harm people and pet birds. | `packages/core/src/preflight.rs` |
| Bed temperature and plate type | The bed temperature comes from the plate type the print uses (cool, engineering, high temp, textured PEI, supertack, textured cool). A filament with no temperature for that plate type warns. Bed temperatures above the printer's bed limit (150 degrees C when unknown) are lowered to it, with a warning. | `packages/core/src/preflight.rs` |
| Chamber temperature | When the printer's chamber limit is known, a filament's chamber target above it is lowered to the limit, with a warning. | `packages/core/src/preflight.rs` |
| Abrasive filament on a soft nozzle | After slicing, the hardness each used filament needs (`required_nozzle_HRC`) is compared with the nozzle's (`nozzle_hrc`, else its nozzle type). A soft nozzle warns, and so does a nozzle whose hardness is unknown. The material planner stops a plan that puts an abrasive material on a soft nozzle. | `packages/core/src/preflight.rs` (`nozzle_hardness`), `packages/settings/src/plan.rs` |
| Material against what is loaded | Before a send, a filament type that matches none of the printer's loaded slots warns. | `packages/app/src/plate/preflight.ts` |
| Diameters and other impossible values | A nozzle diameter, filament diameter, layer height, first layer height or line width of 0 or less refuses the slice. | `packages/core/src/preflight.rs` |

## Extrusion, motion and layer limits

| Check | What SlicerX does | Code |
| --- | --- | --- |
| Layer height against nozzle diameter | The engine lowers a layer height or first layer height taller than the nozzle to the nozzle diameter, and raises one below 0.04 mm to 0.04 mm, each with a warning. The settings checker marks a layer taller than the nozzle as an error and suggests 75 percent of the nozzle, warns above 75 percent, and warns outside the printer's minimum and maximum layer height. | `packages/core/src/preflight.rs`, `packages/settings/src/validate.rs` |
| Line width | A line width outside 10 to 250 percent of the nozzle diameter is pulled into that range, with a warning. | `packages/core/src/preflight.rs` |
| Maximum volumetric speed | Every path's speed is lowered so the flow stays under the filament's `filament_max_volumetric_speed`, before the time estimate is made. The settings checker warns when a speed asks for more. | `packages/core/src/preflight.rs` (`cap_speeds`), `packages/settings/src/validate.rs` |
| Machine speed limits | Print speeds above the printer's X and Y speed limits are lowered to them, with a warning, and every path is held to them. On Marlin and RepRapFirmware the machine limits are written into the G-code (`M201`, `M203`, `M204`, `M205`, or `M566`) when the profile asks for them. The settings checker warns when the acceleration is above the machine's. | `packages/core/src/preflight.rs`, `packages/core/src/firmware.rs`, `packages/settings/src/validate.rs` |
| Spiral vase conflicts | The settings checker flags spiral mode with more than one wall, with infill and with support. | `packages/settings/src/validate.rs` |
| Settings conflicts | The settings checker validates every key's type, range and choices and checks conflicts between keys. Each finding has a code, the keys it concerns, a message and, where there is one, a suggested fix that is never applied silently. | `packages/settings/src/validate.rs` |
| Nothing to print | The settings checker reports settings that print nothing, and the engine refuses an empty plate. | `packages/settings/src/validate.rs`, `packages/core/src/error.rs` |
| Open edges, floating regions, thin walls | The slice warns about open mesh edges, regions with nothing under them, long bridges and features too thin for their walls. | `packages/core/src/session.rs` |

## G-code and macros

| Check | What SlicerX does | Code |
| --- | --- | --- |
| Custom G-code (start, end, layer change, tool change, pause, filament) | The engine lints every rendered section before it goes into the file. It refuses heater targets above the printer's limits, negative targets, waits with no target, a placeholder left unfilled, turning off cold extrusion protection, homing or overriding the position mid-print, sections that leave relative XYZ or absolute E set, and an end sequence that leaves the nozzle hot. A deny list covers commands that write printer memory or configuration (`M500`, `SAVE_CONFIG`), restart or update firmware, run shell commands or stored macros, change PID values, steps, probe offsets, motor currents, endstops or network settings, or drive pins. Other state changes (power, leveling, baby stepping, pauses, filament changes, speed limits) warn. Text the person wrote or the app shipped is trusted, and a few deny list commands that stock printer profiles use (such as `M500` and `M211`) only warn there. Text from anywhere else is untrusted: every warning refuses instead. | `packages/core/src/gcode_lint.rs`, `packages/core/src/customgcode.rs`, `packages/core/src/preflight.rs` |
| Post-processing scripts and credentials in files | No file, profile, project or request can set `post_process` or a printer host credential: the engine drops those keys on import, and so do the app's project reader and the MCP server's. | `packages/core/src/preflight.rs` (`is_never_imported`), `packages/core/src/config.rs`, `packages/app/src/export/project-settings.ts`, `packages/mcp/src/projectfile.ts` |
| File sliced for a different printer | Before a send, the file's G-code flavor must be one the printer's connection runs, or the send is blocked. A nozzle size that differs from the one the printer reports, or one the model is not sold with, warns. | `packages/app/src/plate/preflight.ts` |
| Printer busy or in error | A send is blocked while the printer is printing, offline or reporting an error, and while a Bambu Lab printer turns away prints from other apps (Developer Mode off). | `packages/app/src/plate/preflight.ts`, `packages/app/src/plate/guard.ts` |
| G-code in the sent file | The send sheet reads the exported file and warns about flow above the filament's limit and nozzle temperatures outside the material's range. It never blocks. | `packages/app/src/plate/lint.ts` |
| Resume from a layer | A resumed file heats the bed and every tool the plate uses, lifts Z by a relative move before homing X and Y (so the nozzle does not drag through the part), and then prints from the chosen layer. A declared Z (`G92 Z`, or `SET_KINEMATIC_POSITION` on Klipper) must be between 0 and the lower of the printer's height and the sliced part's top, or the slice is refused, and the file warns that the nozzle must be moved to that height by hand. | `packages/core/src/gcode.rs` (`resume_header`), `packages/core/src/api.rs` |

### G-code review

Printer G-code from a project file is reviewed before it runs. Text that is the stock G-code for the printer model, as SlicerX ships it or as it was shipped for that model before, is used as it is (fingerprints in `packages/settings/profiles/stock-gcode.json`). Anything else is compared with the printer profile's text and linted with the same rules as the engine; the result is the diff, each flagged line with its reason, and whether a person may approve it. A change with an error flag can never be approved. Code: `packages/settings/js/gcode-review.ts`.

In the app, the next slice the person starts shows the diff, and they choose the project's G-code or the printer profile's, which is the default. Only the dialog's button chooses the project's (`packages/app/src/state/project-gcode.ts`). The MCP server refuses a slice with such G-code with `project_gcode_review` and the diff, and no tool call can choose the project's G-code. Machine G-code is not editable in the app's printer settings.

### Remote start conditions

Over remote access, an approver phone may approve pausing, stopping and skipping one object, since those only stop extrusion. It may approve a start (a client's print, or a plate already in the queue with no scheduled time) only when all of this holds at the approval:

- the person turned remote start on for that printer (off by default, cleared when the printer is removed), with nozzle and bed limits that default to 240 and 80 degrees C and are held to the printer catalog's limits for its vendor and model, or to the defaults when the catalog does not know it;
- the camera guard is on for the printer;
- the file was read once (at most 512 MB of G-code inside a `.gcode.3mf`, within a time limit) and heats the nozzle and bed within those limits, names its nozzle temperature, sets no chamber target above 0, and contains nothing the reader cannot vouch for (an unknown heater, a start macro given no nozzle temperature, a value that is not a plain number);
- the latest plate check found the plate clear by comparing a still with the person's empty-plate picture, the still was taken after the last print ended and at most 60 seconds earlier, and it is not the same picture as before (a frozen feed); a second check at the approval passes too;
- the person ticked that the plate is clear, signed with the decision.

Right before the start command, a third fresh check must pass the same way, and the start must come within 3 minutes of the approval. No answer, a failed check, a frozen feed, a late start or a hub restart in between refuses it. The audit records each check's time, still hash and verdict. Code: `packages/connect/link/src/remote_start.rs`, `packages/connect/src/heat.rs`.

### Phones over remote access

Any other card (a resume, raw G-code, a home, a filament change, an adjustment, a scheduled plate) can only be denied from a phone over remote access. A partner company's phone app never approves a card a partner app raised, decided by the role the hub recorded for the card's raiser, and approves nothing when no raiser is recorded. A phone that was removed or lost its approve right while the checks ran cannot approve. Code: `packages/connect/link/src/remote_rpc.rs`.

## Motion guard

A raw G-code line goes to a printer one line at a time: 1 to 96 printable ASCII characters, with no line breaks or control characters, so the approval card shows it whole. A line that can move the head goes under the same rules as a home, whoever approved it: a client's card (work kind `gcode`) or a `gcode` call with a person's token. The hub holds the printer lock, reads the printer's state fresh, and sends the line only while the printer is idle or finished (`bad_state` otherwise) and only onto a plate it knows is clear or the person said is clear for the current bed epoch (`bed_check` with `details.epoch` otherwise; an answer for an earlier epoch counts for nothing). Absolute positioning is restored first on an idle or finished printer, as for a jog, and never inside a running print. A raw `G91` that goes through leaves the printer marked, so the next line that moves, jog or start sends `G90` first. A card for such a line carries `motion: true`. Code: `line_rule` in `packages/connect/src/gate.rs`, `line_checked` in `packages/connect/link/src/device.rs`.

The test fails closed. Only `;` starts a comment. A line is read as firmware reads it: any case, spaces after the letter, a line number with any spacing, leading zeros and a checksum. Parameters are read by letter, not by word, so `G92 E0Z50` sets Z. A homing line (`G28` in any spelling, or any line with a parenthesis) goes under the home rules, and a plain `M600` under the filament change rule. Every other line falls in one of four classes:

- Any time, a running print included: heater and fan targets (`M104`, `M106`, `M107`, `M140`, `M141`), messages (`M117`, `M118`), reports (`M105`, `M114`, `M115`, `M119`, `M155`, `M503`), a beep (`M300`), the Klipper commands `SET_HEATER_TEMPERATURE`, `TURN_OFF_HEATERS`, `SET_FAN_SPEED`, `RESPOND`, `STATUS`, `QUERY_ENDSTOPS` and `GET_POSITION`, and a line that is empty or only a `;` comment. A message that carries a host action (`action:resume`, `action:cancel`) is not in this class: it counts as motion, since the host would resume or stop the print around the resume and pause rules.
- Only while no print runs (idle or finished, under the printer lock, no plate question, since the head does not move): `G21`, `G90`, `G92` when its only parameter letter is `E`, `M73`, `M82`, `M83`, `M110`, the waits `M190`, `M191`, `M400` and `TEMPERATURE_WAIT`, a dwell `G4` of at most 60 seconds, and `M220` and `M221` with one `S` from 50 to 150 percent.
- Refused as a raw line: a dwell over 60 seconds or given another way, and an `M220` or `M221` that is not one `S` from 50 to 150 percent.
- Motion, everything else: moves (`G0` to `G3`), `G91`, probing and leveling in every firmware's form (`G29` with the Bambu Lab decimals `G29.1`, `G29.2` and `G29.9`, `G30`, `G32`, `G34`, `G80` and `G81`, `M48`, `G38.x`, and Klipper's `PROBE`, `PROBE_CALIBRATE`, `BED_MESH_CALIBRATE`, `QUAD_GANTRY_LEVEL`, `Z_TILT_ADJUST`, `SCREWS_TILT_CALCULATE` and the like), start macros (`PRINT_START`, `START_PRINT`, Bambu Lab's `M1002`), a `G92` that sets any axis but E or none, motors on and off, `M109` (RepRapFirmware picks a tool on it and runs the tool change macros), filament loads and unloads and tool changes (`M701`, `M702`, `LOAD_FILAMENT`, `UNLOAD_FILAMENT`, `T1`), an `M600` with any parameter but `B`, and any code or macro the lists do not know. So is any line the guard cannot read as one command: text after a checksum, or a line number with no command. A line with a `(` or `)` goes under the home rules (Marlin and RepRapFirmware skip a parenthesized comment, but Klipper runs `(G28` as G28).

A raw line refused for the printer's state that has a control of its own names it: a raw `RESUME` mid-print points to Resume, a raw `EXCLUDE_OBJECT` to Skip object, and a raw `M220` to the print speed control, each with its own checks. `SET_KINEMATIC_POSITION` and unknown macros are refused mid-print. The rule reads one line; it does not know what a macro does inside, which is why an unknown macro counts as motion.

## Software and supply chain

| Check | What SlicerX does | Code |
| --- | --- | --- |
| Library upload scanning | Every upload to the free library is treated as hostile. It is size capped (150 MiB a file, 300 MiB an upload), checked against a SHA-256 blocklist, scanned with ClamAV before anything parses it (a scanner that cannot answer means not approved), typed from its content, and audited as an archive before anything is inflated. Only known parts are kept, the archive is rebuilt, the mesh is parsed and checked, and the result is checked against the blocklist and scanned again. The whole check has a time limit. | `editions/slicerx/packages/cloud/scan/src/lib.rs`, `editions/slicerx/packages/cloud/scan/src/archive.rs` |
| Opening a 3MF locally | An archive entry may inflate to at most 1 GiB, component nesting is followed at most 16 deep, and the work one file may ask of the component resolver is capped, so a few lines of XML cannot ask for billions of copies. | `packages/core/src/threemf.rs`, `packages/geom/src/import/container.rs` |
| Settings and G-code carried by a project 3MF | A project file is untrusted input. Only plain numbers, switches and choices of the print and filament settings are taken, and the few text settings whose grammar the app checks (the infill angle templates and extra solid infill layers). Other free text, `post_process`, network and credential keys, and the printer's own settings are left out. A project made for a printer SlicerX has a profile for opens on one of the person's printers of that model and nozzle, with that printer's G-code, or else as a project printer of its own that exports G-code and uses the project's machine G-code, except text with lines the G-code check never allows, which stays the profile's. Switching to another printer takes that printer's G-code in full, so no project G-code reaches another machine. Printer G-code in any other project goes through G-code review above. | `packages/app/src/export/project-settings.ts`, `packages/app/src/project/project-printer.ts`, `packages/app/src/state/project-gcode.ts` |
| Credentials | Printer credentials are kept in the OS keychain (macOS Keychain, Windows Credential Manager, Secret Service) and never appear in debug output, logs or error text. On Windows, a credential the keychain refuses to write goes into a file of its own in the app's data folder, encrypted for that Windows user with DPAPI; no other system writes one to a file. An approval token hides its token in debug output. Error text from model providers has API keys and bearer tokens removed. | `packages/connect/src/secrets.rs`, `apps/desktop/src-tauri/src/vault.rs`, `packages/connect/src/gate.rs`, `packages/pilot/src/node/index.ts` |
| Dependency and license checks | CI runs `cargo-deny` for licenses, bans, sources and advisories, and `reuse lint` for every file's license. | `deny.toml`, `.github/workflows/ci.yml` |
