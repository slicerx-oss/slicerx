# Benchmarks

The reference for every SlicerX slicing number.

- Reference machine: Apple M3 Pro, 11 cores (5 performance, 6 efficiency), 18 GB. Numbers from other machines are informative only.
- Reference model: `models/x-mark.stl`, the SlicerX X on a plinth (26,268 triangles, 85.5 mm tall), generated by `models/generate.py` (Apache-2.0, see `models/LICENSES.md`).
- Reference settings: `configs/reference-0.20.json`: 0.20 mm layers, 2 walls, 15 percent rectilinear infill, 0.42 mm lines, top 5 and bottom 3 shells, 5 mm brim, no supports. 427 layers.
- `configs/baseline-reference-0.20.json`: the accepted extrusion total the gate compares against (the first run that passed every other gate). It stays fixed while tuning, so drift adds up in the delta instead of hiding.

## Gates

A speed number counts only if the same build passes: the expected layer count, no errors from the G-code validator in `sx-core` (no negative extrusion on a move, no move outside the bed, Z never goes down), total extrusion within 1 percent of the accepted baseline, and identical G-code and SXPV hashes when the plate is sliced as 1, 4 and 11 layer ranges. `sx bench` checks all of them and exits 1 when one fails.

## Tools

- `sx bench --config configs/reference-0.20.json --runs 15 --warmup 3`: the full pipeline (plate preparation, slicing, G-code into memory, SXPV), median and p90, stage times and the gates. `--threads N`, `--incremental sparse_infill_density` (re-slice with the prepared plate kept), `--ab <other sx>` (interleaved A/B).
- `run-remote.sh`: syncs the tree to the reference machine (`SX_BENCH_HOST`), builds `sx` with `--profile bench-release` and runs `bench`, `snapshot <name>` (keeps a copy of the built binary outside the tree) or `ab <name>` (interleaved A/B against a snapshot).
- `climb.mjs`: one step of speed tuning: A/B against the last kept build (15 rounds, each the median of 3 runs after 2 warmups), the full gated bench and a single-thread run, then one line in `results.jsonl` and one row in `LOG.md`. A change is kept when it is at least 2 percent faster and every gate passes; `--fix` keeps a correctness fix whenever the gates pass.
- `web-slice.mjs`: browser timing through headless Chrome (Playwright). It serves `../web/bench` with Vite, opens fresh pages and reports the median first slice (request to result), warm slice, pool start and mesh load. `--ab "<query A>" "<query B>"` interleaves two variants page by page; `--append` logs to `web-results.jsonl` and `WEB-LOG.md`.
- `models/`: the reference model and its generator.

```
SX_BENCH_HOST=<host> sh packages/core/bench/run-remote.sh bench --runs 15 --warmup 3
SX_BENCH_HOST=<host> node packages/core/bench/climb.mjs --change "one sentence on the change"
pnpm --filter @slicerx/slicer build:wasm && node packages/core/bench/web-slice.mjs --pages 9
```

## Status

Speed tuning so far (`LOG.md`, 22 steps on an earlier plate of similar size, 11 kept) took the native median from 70 ms to 17 ms. The largest steps were replacing a general polygon offset with a miter offset plus crossing check (70 to 35 ms) and cleaning cut contours to 0.0125 mm (26 to 18 ms). The browser pool reached 55 ms in Chrome on the same plate (`WEB-LOG.md`) after spreading layer ranges over the workers from a shared queue and warming each worker up with a small slice.

Numbers for `models/x-mark.stl` on the reference machine are measured once it is free of other load and will be listed here.

Two colors against OrcaSlicer 2.4.2, on `models/x-mark-2color-orca.3mf` with the shared settings of `compare/settings.py` (2026-10-11, SlicerX e5b5da39): both slice 427 layers with filament 2 from z 15.8 to 85.4. SlicerX extrudes 9010 mm (5657 and 3353 per filament) and Orca 9035 mm (5673 and 3362), 0.3 percent less. By feature, in mm of filament, SlicerX against Orca:

| Feature | SlicerX | Orca |
| --- | --- | --- |
| Sparse infill | 3181 | 3181 |
| Internal solid infill | 1780 | 1800 |
| Outer wall | 1608 | 1608 |
| Inner wall | 1578 | 1578 |
| Internal bridge | 359 | 361 |
| Top surface | 181 | 185 |
| Bottom surface | 137 | 137 |
| Brim | 82 | 83 |
| Bridge | 60 | 60 |
| Overhang wall | 43 | 43 |

The settings pin `filament_flow_ratio` and `bridge_flow` at 1 for every slicer. A project file carries its own values, and Orca keeps the project's for any key the preset leaves out: left out, Orca took Generic PLA's 0.98 flow ratio from this project and printed 2 percent less on walls and infill, and took the project's `bridge_flow` of 0.95, which printed overhang walls and bridges at 0.382 mm wide. That second one made overhang walls read 55 against 41 mm here before. Orca reads a user preset's values only as strings: a number in the preset JSON is skipped without a warning. On one color (`x-mark.stl`) the comparison agrees to 0.2 percent (8.55 m against 8.57 m), and overhang wall is 6.3 mm in both. The 2-color speed baseline (`configs/baseline-x-mark-2color-0.20.json`) has not been moved for this.

Bridge path length still differs: on one color SlicerX draws 471 mm of bridge lines to Orca's 488, and with `bridge_flow` below 1 Orca packs its bridge lines closer while SlicerX keeps the same spacing (2010 against 2131 mm at 0.95 on two colors).

Interleaved A/B runs still vary by a few percent when the machine has other work, so single gains near the 2 percent line are within noise.
