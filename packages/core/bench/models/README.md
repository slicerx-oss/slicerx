# Reference models

`x-mark.stl` is the reference model for SlicerX benchmarks, tests and examples: the X from the SlicerX logo standing upright on a small plinth. It is generated by `generate.py` (Python 3, standard library only), so it is ours to use and share under Apache-2.0 (see `LICENSES.md`).

The model is built to exercise a slicer rather than to look pretty:

- eight horizontal bands, alternate bands set 0.6 mm into the front and back faces, with a shallow groove between bands (steps on every band boundary give top and bottom surfaces all the way up)
- the diagonal arms of the X overhang at about 40 degrees from vertical, and the arms meet in a crotch above and below the center
- rounded edges (1.5 mm) on the X and the plinth, which give curved walls on every layer
- a 6 mm plinth fused to the X, so the first layers are a wide solid area with a brim around it

| File | Triangles | Size (mm) | Layers at 0.20 mm |
| --- | --- | --- | --- |
| `x-mark.stl` | 26,268 | 84.7 x 26.0 x 85.5 | 427 |
| `x-mark-2color.3mf` | 21,908 + 14,128 (two parts) | same | 427 |
| `x-mark-2color-orca.3mf` | the same two parts | same | 427 |

`x-mark-2color.3mf` splits the same X by band into two closed parts: the plinth with the first, third, fifth and seventh bands on filament 1, the other four bands on filament 2 (set in the file's project metadata), so a slice has a tool change at every band boundary.

`x-mark-2color-orca.3mf` is the same geometry as an OrcaSlicer 2.4.2 project, saved from Orca's own GUI: one object with the two parts as normal parts, part 2 on filament 2 at z 15.5 to 85.5. Orca cannot slice `x-mark-2color.3mf` itself: as two objects it crashes, and as one object built from its command line it drops part 2, whose bands do not touch each other. SlicerX slices both files the same way. Use this one when comparing with Orca on two colors.

Regenerate:

```
python3 generate.py                      # both files
python3 generate.py --check x-mark.stl   # triangle count, size, open edges, volume
python3 generate.py --twist-deg 30 --taper 0.2 --out twisted.stl --out-2color ""
```

Options: `--height` (of the X, default 80 mm), `--thickness` (16 mm), `--twist-deg` (0), `--taper` (0), `--cell` (mesh grid size, 1.2 mm; smaller gives more triangles). Output is deterministic. The default files are closed and consistently oriented (no open or repeated edges); strong twist can leave a few repeated edges where the surface folds, which slicers tolerate.

## Speed benchmark models

`suite.py` writes the models of the speed benchmark against other slicers, each a kind of print people make: `tug` (a 60 mm boat with overhangs, bridges and holes, 154,036 triangles), `holes` (a 200 x 140 x 4 mm plate with 70 holes, 27,968), `spire` (180 mm tall, 14 mm across, 138,432), `knot` (an organic shape that needs supports, 138,240), `dense` (1,200,000) and `plate20` (10 gears and 10 small tugs, 332,440 in all). Each comes as STL and as a 3MF placed on a 256 mm bed; `plates.json` gives the same placements for engine requests. The files are generated on demand and not kept in the repository:

```
python3 suite.py <out dir>               # every model
python3 suite.py <out dir> tug holes     # only these
```
