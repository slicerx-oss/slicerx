### Added

- `slicerx_partner_routes` 1.0.0: reads the partner routes open on the SlicerX hub, each a partner app's sealed byte stream between its desktop app and its own paired phone over the relay. Each route has `routeId`, `app`, `pairingId`, `phone`, `state` (`opening` or `open`), `openedAt`, `lastAt`, `bytesIn`, `bytesOut` and `refused`; `caps` has the hub's `maxRoutes` and `maxChunkBytes` and the relay's partner caps and this account's use of them today. Optional `app` narrows the list to one partner app. Sizes and times only: the bytes and the relay routes never reach a client, and no tool opens or closes a route. Simulated printers are refused with `not_supported` and `details.reason` `no_hub`.
- `slicerx_remote_start_policy` 1.0.0 reads, for each printer or one with `printerId`, whether a paired phone away from home may approve starting a print there: `enabled` (the person turned remote start on in the app, off by default), `maxNozzleC` and `maxBedC` (the hottest file it lets through, 240 and 80 °C by default), `guard`, and `plateCheck`, the printer's last camera plate check (`checkedAt`, `clear`, `compared`, `passes`, and `reason` when it does not pass). The answer has `plateWindowSeconds` (60) and `chamber` (`never`). No tool changes the setting; the hub refuses `remoteStart.set` from an agent connection.
- `slicerx_printer_queue_start` 1.0.0 asks a person to start a plate already in the hub's queue, now: with `itemId` (class `queue`, so the user's policy decides whether it runs, asks or is off) the hub raises that plate's card, which says who asked, and starts it once a person approves in the app, at the printer or on a paired phone under the remote start rule. Declining that card leaves the plate in the queue. Without `itemId` it lists the open queued plates as the hub shows them to clients (id, printer, name, state, start time; no file hash, options or card). It never starts a print or answers the card. Refusals: `busy` while a print is on the plate, `invalid_input` with `reason` `bad_state` for a scheduled plate or one that left the queue, and `not_found`.
- `slicerx_print_adjust` 1.1.0 takes `change` `{kind: "skip_object", objectId}`: skip one object of the running print, by its id from the printer's object list. The card waits for a person, who may approve it on a paired phone away from home, since it only stops extrusion for that object. The skip names the running print by its bed epoch, read from the hub and hashed with the object.
- The hub lets agent and partner connections read `queue.list`, redacted (a partner sees only plates it queued), and ask for a queued plate's card with `queue.start`; queueing a plate stays with the app.
- `slicerx_app_parts`, `slicerx_app_part_clone` and `slicerx_app_parts_order` 1.0.0: read the parts of an object open in the app, clone one part inside its object (named like "Body 2", with its filament, print settings and paint, beside it on X), and put the parts in a new order by a full order or by moving one part. Each edit is one Undo in the app and reads the parts back; with a CAD history, a clone records a `parts.add` step and a reorder a `parts.order` step. They need the app link and an edit grant (app link methods `parts.list`, `parts.clone` and `parts.order`).
- `slicerx_mimir_session` 1.1.0: a question the person answered on their paired phone carries `answeredOn` (`kind` `phone` and the phone's name) on its turn's question step, so a client can tell who answered it and from where. No tool picks an answer; a client still only turns a question down with `slicerx_mimir_dismiss`.
- `slicerx_step_read` 1.3.0 plans a filament for each body color, as the app does when it opens the file. It takes `filaments` (the project's filament colors, filament 1 first; unset, a new project) and `max_filaments` (such as the printer's slot count, default 16). Each body has `filament` (null without a color) and `filament_match`: `match` for a filament within CIEDE2000 12 of its color, `new` for one of `filaments_to_add` (number and color), `nearest` when no filament is close and none can be added. Colors close to each other share one new filament. The read changes nothing.
- `slicerx_project_add_model` 1.2.0 takes a STEP or IGES file: an object per object of the file with a part per body. With `body_colors` `apply` (the default) each colored body prints with the filament `slicerx_step_read` plans against the project's filaments, and the filaments it needs are added with their colors; `ignore` loads every body on filament 1. The answer lists each object's `part_filaments` and the `filaments_added`, and `slicerx_project_show` reads the filaments back. It needs the optional STEP reader, as `slicerx_step_read` does.
- `slicerx_step_read` 1.2.0 reads IGES files (`.igs`, `.iges`) too, into the same answer as a STEP file: objects of touching bodies, body names and colors, triangle counts and boxes in mm, the declared `unit` and `notes`, and STL or OBJ output. An IGES file of loose trimmed surfaces and no solids, as many CAD programs write IGES, is sewn into closed solids where its surfaces close, and the surfaces that do not close become a body per group of touching surfaces, with a note saying which. Two new refusal codes: `step_not_iges` and `step_iges_compressed` (the compressed IGES form). Its title is now "Read a STEP or IGES file". It needs the `@slicerx/step-reader` from the same kit; an older reader still reads STEP files, and an IGES file is refused with `not_supported` and the install line.
- `slicerx_open_in_app` 1.2.0 opens `.igs` and `.iges` files in the desktop app, which registers both.
- `slicerx_geom_loft` 1.0.0: a solid through 2 to 64 closed sketch profiles in order (`profiles`, each `frame` and `loops` as for `slicerx_geom_revolve`), with straight sides from each profile to the next and flat ends, as a new body (`operation` `new`), joined to a target or cut from it. Profiles are matched corner to corner with the least twist, so a square lofts to a circle. Each profile is one closed loop without holes; neighboring profiles that touch or cross each other's plane are refused with the profile numbers. With `design` it adds a `sketch.loft` step that replays and saves in the 3MF like every other step, and takes finished sketch ids as `sketches` instead of `profiles`; without one it writes an STL with volume, bounds and whether it is watertight. App link method `geom.loft` (edit class).
- `slicerx_slice_file` 1.5.0 returns `prime_tower` with the sx engine when the plate prints one: its front left corner on the bed, width and depth in mm and its turn in degrees, and the text answer says where it stands. A smooth timelapse on a Bambu Lab printer (overrides `timelapse_type` "1") prints one on every layer with one filament too; with `enable_prime_tower` off the warnings say the shots are taken as in a traditional timelapse.
- `slicerx_slice_file` 1.4.0 takes `preview_format` with `preview`: `v1` (the default, as before) or `v2`, which writes the SXPV preview as v2, the same toolpaths in about a fifth of the bytes, layer by layer. `readPreview` in `@slicerx/contracts` (and so `@slicerx/embed`) reads both; a reader of your own needs the v2 expander first. v1 stays the default until a later release.
- `slicerx_cloud_jobs` 1.2.0 returns `collisions` for a job whose result has any, and in each plate of a job that named plates, as `slicerx_slice_file` lists them: the object printing by its id and name, what it meets (`hit_kind` object, tower or zone), the object struck, layers from 1, and the place and region struck in plate mm, from the printable area's front left corner. `result` no longer repeats the engine's own `collisions` and `collisionPlate`; its `collisionFixes` stay as the engine wrote them, and their `clears` index this list. A job stored before the cloud kept the plate (a result with collisions and no `collisionPlate`) gets no `collisions`: its result keeps the engine's own `collisions`, each plate gives them as `engineCollisions`, both in machine coordinates with objects by id, and `collisionsNote` says so.
- `slicerx_print_watch_status` 1.1.0 reads the camera guard too. Each printer's row has `guard` (the guard watches that printer; false when the person turned it off), `guardTrip` (its current trip: `kind` `hand` or `plate`, `state` `paused`, `alert`, `blocked` or `clear`, `at`, and when the guard could tell `box`, `note`, `confidence`, `monitorOnly`, `startedBy`, `plateFrom`, `capturedAt`, `answered` and `answeredBy`; null with no trip) and `guardPlate` (when its empty-plate picture was taken, or null). The answer has `detector`, whether a failure detector is connected to the hub. A hub that does not answer `watch.guardState` to an agent leaves all four null. The trip's frame stays in the app, and no tool turns the guard on or off or answers a trip.
- The hub lets agent connections read `watch.guardState`: trips, the printers the guard is off for, empty-plate picture times and whether a detector is connected, with no frame. Setting the guard (`watch.guard`), its frame (`watch.evidence`), answering a trip and the plate and hand checks stay with the app.
- `slicerx_cloud_slice` 1.1.0 takes a 3MF project as well as an STL, and `plates` (1 to 32 plate numbers): the job slices only those plates, each on its own, and each counts as one of the account's daily cloud slices. Without `plates` a project slices its first plate, each build item an object of its own. A job past the slices left today is refused before anything is uploaded, saying how many are left; `plates` on an STL, or a plate named twice, is refused with `invalid_input`.
- `slicerx_cloud_jobs` 1.1.0 gives a job that named plates its `plateCount`, the plate it is slicing while it runs (`plateIndex`), and `plates`: each plate's status, its error when it did not slice, its time, filament grams, layer count and its own G-code and preview links.
- `slicerx_print_watch_status` 1.0.0: reads the print watch's settings for every printer, or one with `printerId`, as the SlicerX hub holds them: `autoPause` (the person's standing permission for the watch to pause that printer), `huginn` (a second look with one camera frame confirms a finding first), `pausesOnFailure` (true only when both are on, since the watch pauses only a confirmed finding of 0.8 or more), `bedMask`, and `watchedNow` (the printer prints and has a camera, so the hub hands its frames to the detector). `huginn` and `bedMask` are null when the hub does not answer those reads. No tool changes these; the hub refuses the setters from an agent connection. Simulated printers are refused with `not_supported` and `details.reason` `no_watch`.
- `slicerx_printer_queue` 1.2.0 takes `options`, the Print sheet's print options: `bedLeveling`, `flowCalibration`, `vibrationCompensation`, `timelapse` and `firstLayerInspection`, each `true` or `false`. Which ones a printer offers and their defaults come from the same table as the Print sheet, read with the printer's reported model and camera. An option left out takes the printer's default, and the card the person approves lists every option as it will be sent. An option the printer does not offer, such as first layer inspection on an A1 or timelapse on a printer with no camera, is refused with `unsupported_option` before any card, and the message names the options it does offer. The answer returns `options` as sent to the hub.
- `slicerx_pending_approvals` 1.1.0 returns `options` for a print handed to the hub: its print options as sent.
- `slicerx_project_layer_marks`, `slicerx_project_layer_mark_add` and `slicerx_project_layer_mark_remove` 1.0.0: list, add and remove the pauses, color changes and custom G-code at layers on one `plate` of a local `.3mf` `project`, saved in the file as the app saves its layer slider marks (`Metadata/custom_gcode_per_layer.xml`, through the reader and writer the app uses), so the project opens in the app and `slicerx_slice_file` slices them. Each mark has `z_mm` (its layer top), `kind` (`pause`, `color_change`, `tool_change` or `custom`), `gcode`, `slot`, `skipped` for a tool change kept but not applied, and `refused` for custom text the app leaves out. Add (`z_mm`, `kind` of `pause`, `color_change` or `custom`, `gcode`, `slot` for a color change) replaces a mark at the same height. Custom G-code always asks the user first, even when the policy allows slicing, and text the app refuses (printer memory or configuration, motors off, firmware, a stop, or past 350 C nozzle or 130 C bed) is refused with `invalid_input`. Remove takes the mark's `z_mm` and refuses a height with no mark with `not_found`. Both answer with the plate's marks read back from the saved file and refuse a plate the project lacks (`no_such_plate`) and a file holding sliced G-code (`not_supported`).
- `slicerx_project_mirror` 1.0.0 mirrors one object or a list along `axis` x, y or z, as Mirror does in the app: in place about the middle of its box, every copy with it, back on the bed. The mirror reads back as a negative `scale` on that axis, with the rotation about the other two axes turned the other way, and a locked object is refused before any of the list changes. `slicerx_project_fill_bed` 1.0.0 fills the free room on one of the object's plates (`plate`, default its first) with copies of it, as Fill bed does: up to `max` (100) more, `spacing` mm apart (default 6), nested on their outlines at any turn (on their boxes without the geometry engine) around every copy already there, which stays put. It answers with `added`, the object's `copies` on the plate and the project; a bed with no room adds none, and an object too large for an empty plate is refused. `slicerx-mcp call` runs both from a shell.

- `slicerx_mimir_dismiss` 1.0.0: turns down the question mimir is waiting on in the open app (`askId`, optional `said` of up to 1000 characters). mimir carries on without an answer and reads `said` in its place; the tool never picks an answer and never stops mimir's run. Answers with `sessionId`, `askId` and `dismissed: true`. Refused with `not_found` when no question waits or `askId` is not the one waiting, `invalid_input` for a `said` over the limit, and `not_configured` while the mimir tab is closed. App link method `mimir.dismiss` (edit class).
- `slicerx_mimir_session` returns `waiting`: the question mimir waits on now (`askId`, `title`, `question`, `choices`), or null. A question turned down shows in its turn's steps with `dismissed: true` and `said`, and `stats.questionsDismissed` counts them.

- `slicerx_inspect_project` 1.2.0 returns `project_printer`: the printer another slicer's project was made for (`name`), and when SlicerX has a profile for it, the `machine:` profile (`profile`) and `nozzle` that slice it on that printer. PrusaSlicer's model codes count, so an `MK4IS` project names `machine:prusa-mk4`. The text adds a "Made for" line.
- `slicerx_slice_file` and `slicerx_estimate_file` return `project_printer` for a project sliced with `project_settings` and a `machine:` profile, with `used` saying whether the slice was for the project's printer. When it was not, a `project_printer` notice names the profile to slice with instead. The slice stays on the printer the call named.

- `slicerx_slice_file` and `slicerx_estimate_file` 1.3.0 take `placement`: `center` (the default, as before) centers a 3MF plate on the bed as a whole; `keep` slices each part where the file puts it, from the front left corner of the printable area (a part at 80, 100 in the file lands at 80.5, 101 on the Snapmaker U1). With `keep`, a part that lands off the bed is refused with `invalid_input` and `details.reason` `off_bed`, the message naming the part and its overhang in mm. An STL or OBJ is centered either way.

### Changed

- `slicerx_printer_queue` sends the printer's Print sheet defaults when `options` is left out, so a Bambu Lab start carries bed leveling, timelapse and the rest as the Print sheet would send them. Before, it sent no print options and the printer used its own. The card lists them.
- SlicerX's approval card for a print a client asked for names each print option as the Print sheet does, such as "Bed leveling off", instead of its key ("bedLeveling false").
- `slicerx_project_scale` 1.1.0 keeps a mirror: an axis `slicerx_project_mirror` mirrored keeps its negative scale.
- `slicerx_mimir_ask` says in its description that it is refused while mimir waits on a question, and that `slicerx_mimir_dismiss` clears it.
- `slicerx_slice_file` and `slicerx_estimate_file` name the arguments they do not take instead of dropping them without a word: the call still succeeds, and a warning (in `warnings`, the text and `notices` with the code `ignored_arguments`) lists each one. For `printer`, `process`, `filament` and `machine` it points to `profiles`, such as `"profiles": ["machine:snapmaker-u1", "process:standard"]`. Before, `{"printer": "Snapmaker U1"}` sliced on the generic machine with only the `no_printer` notice. A later release may refuse unknown arguments.
- `slicerx_arrange` without the geometry engine (no sx-geom, or it fails) sets the copies it moves to a new plate in the middle of the bed, as the nest does and as the app's Arrange now does without the engine. Before, they stayed in the front left corner. When the middle would put a copy on an excluded area, the prime tower's room or past the bed edge, or a skirt round the whole print across an excluded area, they stay where they packed.

### Fixed

- `slicerx_slice_file` and `slicerx_estimate_file` with `project_settings` keep a project's own values that equal the printer's Standard process when the plate starts from the goal nearest its layer height. A project on 0.12 mm layers with 0.2 mm support gaps sliced with the Fine goal's 0.12 mm gaps on its own printer and on others, whether the file listed the gaps as changed, inherited them, listed nothing, or came from another slicer.
- A client on the MCP SDK that lists the tools and then calls `slicerx_step_read` reads its answer. Before, the call failed with -32602 ("Structured content does not match the tool's output schema"), and so did `slicerx_slice_file` and `slicerx_estimate_file` whenever their answer had `collisions`. The listed schemas wrote each fixed-length list, such as a box corner or a point, as `prefixItems` with `items: false`. The SDK client checks answers with a draft-07 validator, which skips `prefixItems` and reads `items: false` as a list with no items, so it refused every box and point. These lists are now listed with `prefixItems`, `minItems` and `maxItems` and no `items`, in the output schemas of those three tools and the input schemas of 36 more (the geometry tools among them). A 2020-12 reader checks them exactly as before.
- `slicerx_inspect_project` reads a project whose main model is over 64 MiB unzipped, such as a project from another slicer that keeps all its geometry in `3D/3dmodel.model`, and so do `slicerx_slice_file` and `slicerx_estimate_file` with `project_settings` or `plate` and the layer mark tools. Before, each was refused with `invalid_model` ("3D/3dmodel.model is over the 67108864 byte limit"), so the file could not be used at all. The app that wrote the file is read from the start of the model only, and a project with no plates of its own still counts its printable build items as one plate. A main model up to 512 MiB unzipped is read. Opening such a file as designs no longer stops at the 64 MiB limit before the engine reads it.
