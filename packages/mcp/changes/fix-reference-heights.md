### Changed

- `slicerx_design_lookup_sizes` 1.2.0 (from 1.1.2), in the mimir tab, tags each found size whose name measures a height from a reference with that reference in `from`: "Funnel height above keel" and "Height keel to funnel top" carry `from: "keel"`, "Spire height from the ground" carries `from: "ground"`. A part's own size ("Funnel height") has no `from`. `size`, `mm` and `said` are unchanged.
- `slicerx_design_plan` 1.19.0 (from 1.18.0), in the mimir tab: its `real` says that a real size measured from a reference (above keel, above deck, above ground) gives where the part's top sits, not the part's own height.

### Fixed

- `slicerx_design_plan` 1.19.0 (from 1.18.0), in the mimir tab: a real size measured from a reference ("height above keel") is held against where its part's top sits: the top of what the part stands on plus its own height, at the plan's scale and within the same slack as any real size. A part stands on the feature its `on` names, a level on the level below it, a main body on the bed, and any other part on the main body with the most bulk. The reference is the lookup's `from` tag, or else the words of the size's name. A keel, base or ground is the bed, a planned part by name is that part's top, and a deck or roof is the top of what the part stands on. A top off scale is refused with a line that says the size gives where the top sits, then the planned top against the one the real size gives. The same holds when the plan ties the looked-up size to the part's own height. Before, the row was refused as "has no size named height above keel; tie the real size to one of its sizes", and a plan that tied it to the part's height made the part as tall as the whole height from the keel. A repeated part's height counts as held by such a row. A reference the plan has no height for (a waterline, sea level, a part it does not plan) is read by the part's own sizes as before.
- `slicerx_design_put_plan` 1.10.1 (from 1.10.0) holds a client plan's real size measured from a reference the same way.
