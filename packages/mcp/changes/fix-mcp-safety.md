### Fixed

- Tools that change what the open app shows, a display preference, this server's working project or a file are no longer listed as read-only. `slicerx_app_ui_set`, `slicerx_app_plate_show`, `slicerx_app_look_set`, `slicerx_app_units_set`, `slicerx_app_pick_filter_set`, `slicerx_app_preview_set`, `slicerx_app_preview_markers_set`, `slicerx_app_preview_playback_set`, `slicerx_app_preview_gcode_jump`, `slicerx_app_select_other`, `slicerx_app_model_push_set`, `slicerx_app_dimensions_show`, `slicerx_app_paint_preview`, `slicerx_app_paint_from_texture`, `slicerx_project_open`, `slicerx_project_add_model` and `slicerx_sxlock_open` now have `readOnlyHint: false`. `slicerx_project_open` is marked destructive, since it replaces the working project, and `slicerx_project_add_model` and `slicerx_sxlock_open` are marked open world. Their permission class is still read, so the policy runs them as before.
- More read class tools that change something are no longer listed as read-only: `slicerx_mimir_ask` (also open world, since it sends a message and up to 4 files), `slicerx_mimir_dismiss`, `slicerx_app_sheet_ask`, `slicerx_design_open`, `slicerx_design_put_plan` and `slicerx_paint_preview`. The server now lists `readOnlyHint: true` only for a tool that says it changes nothing, so a tool that leaves it unsaid is never shown as read-only.
- A model link (`model` on `slicerx_slice_file`, `slicerx_estimate_file`, `slicerx_project_add_model` and the other tools that take a path or an http(s) URL, and `file` on `slicerx_open_in_app`) reaches public internet addresses only. The server resolves the host itself, checks every address it resolves to, and connects to the checked address. Loopback, private (10/8, 172.16/12, 192.168/16, CGNAT 100.64/10, IPv6 fc00::/7), link-local (169.254/16, fe80::/10), unspecified, multicast, reserved and cloud metadata addresses (169.254.169.254, fd00:ec2::254 and others), and IPv6 addresses that carry an IPv4 address, are refused with `path_not_allowed` before anything connects. Redirects are followed by the server, at most five, and each hop gets the same checks; a redirect to a scheme other than http or https is refused with `unsupported_format`. Before, the download followed redirects anywhere, including this computer and the local network.
