### Changed

- `slicerx_arrange_file` 1.1.0 takes the app's Arrange options: `step_deg` (the turn step, 10 by default), `effort` (`quick`, `normal` or `thorough`, how long the search runs, counted work so the same plate gives the same layout anywhere), `keep` (ids of parts that stay where they are while the others are packed round them, as the app's Arrange selection does; a kept part is not listed in `objects`, and an id the plate does not have is refused) and `new_plates` (the parts with no room laid out on new plates in the same call, returned in `plates`, each plate as an arrange of the parts still left lays it out). Printing by object it also returns `order`, the print order the layout takes when it is not the plate's own: when the layout in the plate's order still has a strike the plate check is sure of and its one-click new order clears it (a part taller than the gantry rod printed after the low ones under its gantry), the arrange takes that order, and `slicerx_slice_file` with `placement` `arrange` prints in it. Printing by layer with support on, a part keeps room for its support pad only when it gets support; a part standing wholly on another part's top (a figure on its plinth) gets none. The desktop app's Arrange runs the same engine call, so the app and this tool give the same layout for the same plate and settings.
- `slicerx_cloud_slice` 1.2.0 names the arguments it does not take instead of dropping them without a word, as `slicerx_slice_file` and `slicerx_estimate_file` do: the job is still queued without them, and the result's `warnings`, `notices` (code `ignored_arguments`) and text list each one, pointing `printer`, `process`, `filament` and `machine` to `profiles`. A later release may refuse unknown arguments.
