### Changed

- `slicerx_design_plan` 1.15.0 (from 1.14.0), in the mimir tab: the refusal of a tier list keyed by a name over separate bodies now ends with a worked example of the separate-bodies reading in the plan's own names, in the compact JSON the tool takes: "If they are separate bodies, give each its own list: {"Lower deck house":["Lower deck house"],"Middle deck house":["Middle deck house"],"Boat deck":["Boat deck"]}". Before, it stopped at "give each its own list", and that change refuses no plan taken before. A display or fine plan with real sizes and a scale is also held to real sizes for what sets how it reads: each level of a tier list of two or more levels needs its real length (or its size across when it has no length), and a repeat built as a pattern with a spacing needs its part's real height and the pattern's real spacing. A missing size is refused with the sizes named: "real: a level's length and a repeated part's height and spacing are held to scale too, so give the real Promenade deck length, Boat deck length, Funnel height and Funnels (array) spacing, each tied to its size; for a size the source does not give, say so in assumptions as "real: Funnels (array) spacing not given by the source"". An assumption in that form takes the size's place, and one that starts with "real:" but names none of them is quoted back with the right wording. A tier list of one level, a repeat with no pattern or no spacing, and a plan with `real: []` are not asked for anything new. The description of `real` says so.
