### Fixed

- `slicerx_mimir_run` 1.0.1 reports the last slice as `stale` after any change the slice reads, as the app's own Print and Export check it: a pause or other layer mark, an object renamed, the profile's G-code no longer the shipped text, two objects swapping filaments, a support blocker or modifier, painted supports or seams, a modeling history step edited, the Easy choices (supports, detail, brim), the prime tower, flush volumes (including the nozzle volume and an opened project's own), calibration, the bed, tuned filament presets, the printer's nozzles and extruders, the filament in any printer slot, and a part on another plate moving to a new slot (each plate's G-code lists every slot in use). A slice made right after a filament or printer change is current when it lands. Before, it read only the plate's objects, printer, settings and the filaments in use. mimir's own queue refuses such a slice in the app. A color change's slot note and a spool reload that changes only the grams left still leave it current.
