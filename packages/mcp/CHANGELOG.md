# Changelog

All notable changes to `@slicerx/mcp` are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the package uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- `slicerx_project_height_ranges` takes `layer_height` in a range, as the app sends a project's: the engine prints the layers between the range's heights at that height when every object has the same ranges and nothing else plans the layers (smart layers off, no layer tops).

### Changed

- `slicerx_slice_file` of a 3MF whose objects set their own layer height (object metadata in `Metadata/model_settings.config`) turns off the smart layer heights the default process profile turns on, so each such object slices at its own layer height, and says so in `warnings`. Smart layers asked for in `overrides` stay on, and the engine's warning names the layer heights they replace.
- `slicerx_arrange` (arrange 1.8.0) lays a project's plate out with the nest the app's Arrange uses, when the server has sx-geom (found as before, or the `geomEngine` option): each copy's true outline seen from above, grown by its brim (an automatic brim sized from the copy's first layer, as the slice sizes it), raft and skirt. It keeps clear of the printer's excluded areas (`bed_exclude_area`), the prime tower's room and copies a client placed with `slicerx_project_move`, and the skirt round the whole print, which goes round the tower too, stays off the excluded areas. The tower's room is kept while the plate prints in two or more filaments (in a project, support or a raft in another filament): the tower, its brim and 1 mm, at its spot with `prime_tower_auto_position` off, and at the configured spot pulled onto the bed while the engine places it. How many copies fit a plate is counted on the same outlines. The layout holds until the plate's objects, copies, rotation, scale or bed change; the plate then goes back to the rows, so arrange again after such a change. Without sx-geom, or when it fails, the plate keeps the rows as before. Inputs and outputs are unchanged.

### Fixed

- `slicerx_arrange` leaves room for the first layer of support: grid support (the default for normal support) fills whole cells of its grid past the overhang and its first layer grows 2 mm round that, so the room past a supported part on a 0.4 mm nozzle is about 5.1 mm, not 2.35. A skirt round a supported part at the bed edge no longer runs off the bed.

## [0.2.0] - 2026-10-22

### Breaking

- `slicerx_mimir_dock` is removed, with the docked chat it read. Use `slicerx_mimir_tab`; `slicerx_mimir_ask` and `slicerx_mimir_session` reach the mimir tab's conversation (see Removed).
- mimir's local memory is on by default: `ai.brain.memory.local` in the edition config defaults to `true`, so every edition's mimir gets `memory.remember`, `memory.recall` and the notes block unless the edition sets `local: false` (see Notes for partners).

### Added

- `slicerx_vault_list` lists Vault designs as the open app's Vault shows them, over the app link (`vault.list`, read class). The app reads them with its own store client and the person's session; this server holds no account key or session. `list` is `all` (the approved catalog, signed in or out, the default), `saved` (the person's Saved list) or `mine` (their own uploads in every status), and the last two answer `signed_out` while nobody is signed in. Each design has `id`, `slug`, `title`, `creator` (`handle`, `displayName`), `license`, `tags`, `status`, `publishedAt`, `version` (`version`, `format`, `colors`, `sizeMm` from the upload scan or `null` when it could not vouch for a size, and `print`: the creator's first tested printer with `timeS` and `grams`), `stats` (`downloads`, `makes`, `likes`) and, signed in, `liked` and `saved`. `query`, `tag` and `sort` (`new` or `popular`, with `all` only) filter as the Vault's search, category and sort do, and `limit` (1 to 50, default 24) with `cursor` (`next` from the page before) pages through. It never carries a file, a download link or a token, and never downloads, likes or saves a design.
- The `signed_out` error code, for a call that reads the person's own account data in the open app while nobody is signed in there.
- `slicerx_app_ui` reads the open app's window over the app link (`ui.get`, read class): `workspace` and the `workspaces` the top bar offers, `tab` (`slice`, `design` or `mimir`) and the `tabs` shown, `selection` on the shown plate (`primary` and `objects`, primary first, each with `id` and `name`), `plate` (the plate shown: `number`, `id`, `name`, `count`), `printer` (the one the project slices for: `name`, `vendor`, `model`, `nozzleMm`, `fromProject`; `null` when none is chosen) and `panels` (`open`, `settingsSection`, `settable`). The printer never carries its id, which is a serial on some printers, or an access code or address. `slicerx_app_ui_set` switches the `workspace` or `tab` (`ui.set`, read class), which changes only what the window shows. `slicerx_app_ui_select` sets the `selection` (ids or names, primary first; `[]` selects nothing), opens one panel (`settings` with an optional `section`, `command`, `about`, `shortcuts`, `expert`, `printerChooser` or `printerSettings`; the last three open in Slice) and closes a panel or `all` (`ui.select`, edit class, since the person's next click acts on them; a client allowed to read only is refused). It opens only the panel asked for and closes only the ones named, and answers `busy`, changing nothing, when that would close or cover another dialog or a panel to close has the person's work under way (a command or search typed, an unsaved field in Settings). Both setters answer `busy` while the person has a tool open, a file is opening, the print sheet or a question about an opened project is up, a phone is being paired or first-run setup is up, check everything before anything changes, and answer with the window read back. Neither changes the project: showing another plate stays with `slicerx_app_plate_show`, and the printer is picked by the person.
- `gcode3mf` and the `SliceSummary` type it takes are exported from the package root beside `design3mf`, for hosts that start the server in-process and write a sliced plate's `.gcode.3mf` themselves.
- `slicerx_mimir_run` reads back mimir's print run for one chat in the open app over the app link (`mimir.run`, read class): `steps` (design, plate, target, slice, send and print, each `done`, `now`, `todo` or `off`), `slice` (`timeS`, `grams`, `cost`, `warnings`, `stale`), `send` (`printerName`, `fileName`, `slots`) and `print` (`printerName`, `state`, `layer`, `layerCount`, `timeLeftS`, `progress`, `outcome`), or `null` before the mimir tab first opens. It reads the chat the mimir tab has open, else the newest mimir session, unless `sessionId` names another. It never carries the file, its SHA-256, approval tokens, request ids, printer ids, access codes or serial numbers. Nothing on the app link approves a print, so `slicerx_printer_queue` still waits for the person in the app.
- `slicerx_mimir_memory` reads what mimir remembers about the person in the open app over the app link: printers, filaments, preferences, outcomes and sizes, newest first, with `kind` to read one kind. The app hides access codes, serial numbers and keys before a fact leaves it, and `hidden` counts the facts that had one. `slicerx_mimir_memory_remember` adds one fact (`kind`, `text` of 3 to 240 characters on one line, optional `data` of up to 6 values), with the limits the app's own save uses; it follows the profile class of the permission policy, a fact with a secret is refused, and so is a client the person allowed to read only.
- `slicerx_design_check` checks a built design against a part plan by `planId`: the overall size, each named hole, the feature count, a closed body and the thinnest wall for the nozzle. With the app link on it runs in the app, against the plans the mimir tab made. When the plan is tied to no design and two open designs share the part's name, it asks which. A `design` given ties the client's own plan to it; a plan the person made in the mimir tab is never tied from a client, and a `design` other than the one it is tied to is refused. A plan gets one fix round: when its second check fails too, the result adds `stop`, a plain instruction to stop building and tell the person exactly what is off, and every later check of that `planId` returns that same result with `repeated: true`, without measuring the part again. A new `planId` starts over. A hole row with a `count` is checked as that many holes of its diameter, and its item says how many are short or how many more were found.
- `slicerx_design_put_plan` adds the client's own part plan for `slicerx_design_check` under its `planId`, optionally tied to a `design`, and returns the `planId`. Each `holes` row takes an optional `count` (a whole number from 1 to 60, default 1) for a row that stands for several holes of one diameter, such as four motor screw holes. The client's plan with the same `planId` replaces its old one; the client's last 50 plans are kept apart from the plans the person makes in the mimir tab, which it can never replace or push out (their `planId` is refused). With the app link on it goes to the app (`design.put_plan`, read class), where the app's design check reads it; there is no card on this path.
- `slicerx_mimir_brain` reads the mimir the open app runs over the app link: `name`, `voice` (whether the edition set one), `toolGroups` (each group on or off), `cloud` (`base`, the model mimir cloud answers with, and `stepUp`, the step-up the edition asks for or `null`), `memory` (`local` and `sync`) and `knowledgeDocs`, the count of the edition's own docs. It never carries the voice text or the docs.

### Changed

- `slicerx_design_save` and the `.gcode.3mf` that `slicerx_slice_file` writes with `output: "gcode.3mf"` come from the app's own 3MF writer, so a file saved over MCP opens the same in the app and in other slicers. A saved design now puts its object on plate 1 in `Metadata/model_settings.config`, writes coordinates to 0.0001 mm, writes the build item's transform even at the origin, and adds the `Title` metadata, as the app does. The object keeps its `name` attribute, but its part meshes no longer carry one (their names stay in `Metadata/model_settings.config`). It keeps its CAD history as the design timeline the app saves (`Metadata/slicerx_history.json` version 3, which `slicerx_design_open` reads as before). A `.gcode.3mf` now also carries `Metadata/project_settings.config` with the settings it was sliced with, `Metadata/plate_1.json` with the object boxes, and in `Metadata/slice_info.config` the extruder and nozzle types, the timelapse type, the first layer time, the filament map and each filament's nozzle. Its time, weight and filament use are read from the G-code's footer, as the app reads them, and `first_layer_time` is left out when the G-code does not give it. Tool outputs and file names are unchanged.
- `slicerx_inspect_project` and `slicerx_slice_file` with `project_settings` no longer refuse a project whose `Metadata/project_settings.config` is not JSON. An empty one is read as a project without settings, JSON after a byte order mark is read as usual, and INI style lines or a damaged file are left out: the project opens and slices with the other settings, and `import_report.skipped` says why. `strict_settings` refuses such a file with `project_settings_unused`.
- `slicerx_mimir_tab` 1.1.0 also says whether the model is a local one (`local`, a server the person runs, which gets the shorter tool list) and where its server is (`where`: `computer`, `network` or `remote`, by its address, the same way the memory chip says where notes go; `null` without a model). A local model can run on another computer on the network, so `local` alone never means this computer. mimir has one chat in the app now, the mimir tab, so `tools` lists everything the model is offered there: the design tools, the sheet, questions and lookups, and where the app slices the slicing, printer, settings and project tools and the app commands (among them `app.project_new`, which still asks the person before anything unsaved is discarded).

### Removed

- `slicerx_mimir_dock`: the docked chat is gone from the app. Read the mimir tab with `slicerx_mimir_tab` instead; `slicerx_mimir_ask` and `slicerx_mimir_session` now reach the tab's conversation.

### Fixed

- mimir no longer fails on an OpenAI-style provider when a turn offers more than 128 tools, the provider's limit (which a host's own tools or plugins can push it past). It sends the tools already called in the chat, the core tools and the toolsets the turn needs, fills any room left by a fixed priority up to 128, and notes in the app log which toolsets were left out. Under the limit, and on providers without one, nothing changes.

### Notes for partners

- `ai.brain.memory.local` in the edition config defaults to `true`. Every edition's mimir gets `memory.remember`, `memory.recall` and the notes block in its instructions unless the edition sets `local: false`.
- `Citation.kind` in `@slicerx/contracts` gained `'edition'`, for a source from the edition's own knowledge. Code that switches on `kind` should handle it.
- The `approval_request` pilot event in `@slicerx/contracts` has an optional `source`, the tool's source, so a host's own card for a built-in tool never stands in for a plugin's tool of the same name.

## [0.1.9] - 2026-10-19

### Changed

- mimir now shows a part's sizes on a four-view drawing the person can edit, and waits for Confirm, before it builds a new part. `slicerx_app_sheet` draws all four views when a call names none.

### Fixed

- A tool passed to `createContext` in `extraTools` now replaces a base tool of the same name. The base tool used to win, and the base server adds its CAD tools only when it finds sx-geom, so an embedder's own `slicerx_geom_*` tools were served on a machine without sx-geom and dropped on a machine with it.
- A slice that runs past the engine's time limit (10 minutes) now fails with `slice_timeout` and `details.limitMs`, and says so, instead of `slice_failed` with "sx exited with code -1". A slice stopped by another signal names the signal (`slice_failed`, `details.signal`).

## [0.1.8] - 2026-10-18

### Added

- `slicerx_app_look` 1.1.0 also reads the studio colors: `theme.scene` (the colors in use: top, bottom, glow, plate, grid, edge, xray), `theme.sceneOverrides` (the ones the edition config sets for the active scheme) and `viewport.scene` (the colors the 3D view was given, from the backdrop to the selection outline).
- `slicerx_mimir_dock` reads what answers in the docked mimir chat of the open app over the app link: `link` is `model` when a model answers (with its `provider`, `model`, and `local` when it runs on this computer), `demo` when the built-in demo does, or `none` before the chat is set up; `tools` lists the tools the model is offered there. A local model gets a shorter list without `make_model`, so its prompt and tool schemas leave room for the conversation in a 16K context. It never carries a key or a token.
- Plates over the app link: `slicerx_app_plate_add`, `slicerx_app_plate_duplicate` (objects, copies, paint and settings), `slicerx_app_plate_move` (moves only the object ids given, arranged into free space), `slicerx_app_plate_rename`, `slicerx_app_plate_remove` and `slicerx_app_plate_settings` (bed type, sequence, filament order, slot map and nozzle map per plate).
- The slice preview over the app link: `slicerx_app_preview` and `slicerx_app_preview_set` read and change the visible layers, toolpath colors, camera, toolhead and gantry; `slicerx_app_preview_markers` and `slicerx_app_preview_markers_set` the legend markers (retractions, seams, lifts, wipes, tool changes, pauses); `slicerx_app_preview_playback` and `slicerx_app_preview_playback_set` play, pause, seek and follow the nozzle; `slicerx_app_preview_gcode` reads the G-code behind the slice and `slicerx_app_preview_gcode_jump` selects a line as clicking the G-code panel does.
- Print settings: `slicerx_app_settings` reads the open project's overrides and effective values for the shown plate, and `slicerx_project_set_overrides` sets or clears overrides, such as the `config_patch` from `slicerx_plan_settings`.
- Paint on the shown plate: `slicerx_app_paint` reads an object's color, seam, support or fuzzy paint, `slicerx_app_paint_preview` previews paint without changing it, `slicerx_app_paint_apply` applies that preview and `slicerx_app_paint_clear` clears one layer.
- Brim ears: `slicerx_app_brim_ears` reads them on the shown plate (local and bed positions, diameter, whether each touches the first layer, the brim type in effect, linked copies and a revision), and `slicerx_project_brim_ears` edits them for one object.
- Kept dimensions: `slicerx_app_dimensions` reads every kept reference dimension against the current geometry, `slicerx_app_dimension_keep` and `slicerx_app_dimension_remove` add and remove one, and `slicerx_app_dimensions_show` sets Show all kept dimensions.
- `slicerx_app_pick_filter` and `slicerx_app_pick_filter_set` read and change Model's pick filter (Body, Face and Edge only) and the picked bodies, faces and edges.
- `slicerx_app_units` and `slicerx_app_units_set` read and set Model's display units (mm or in) and precision.
- `slicerx_app_viewport` reads the live view's pixel ratio, motion scale, drawn plate and quality drops (count and the last one's UTC time).
- `slicerx_parts_lookup` gives published sizes, with sources, of a standard part or product (a 608 bearing, NEMA 17, M3, Pi 4, iPhone 15), the same table mimir uses; `slicerx-mcp call parts_lookup` runs it from a shell and `--parts-table` (the `partsTable` option) points at another table.
- `slicerx_walls` makes the walls or floor of a part already in the project thicker or thinner, by a new thickness (`wallMm`) or a change (`byMm`).
- `slicerx_review_script` compares a printer script with versioned stock for the chosen printer and firmware, and `slicerx_prepare_script_replacement` prepares a replacement with verified stock that keeps the original for a printer the client names.
- `slicerx_toolhead_mapping` reads a Snapmaker U1's loaded toolheads and matches each job filament by exact color (Delta E 2 or less), then nearest color, with material breaking ties and unused spools first.

### Changed

- `slicerx_mimir_tab`: with Auto, a build that needs a size only the person knows (a part for their own shelf or desk, a fit to an existing thing, a drawing to read) starts on the larger model.

### Fixed

- Feature filament read-back (`featureFilaments`, `feature_filaments`) stays right for objects split to objects or parts.

## [0.1.7] and earlier

### Added

- `slicerx_app_sketch_boxes` and `slicerx_app_sketch_box_set` read and set the dimension boxes of the sketch open in the app, through the app link: a rectangle's width and height, a line's length and angle from the sketch's X axis, and a circle's diameter. A read lists every shape with its boxes, which dimension sets each one, the sketch's dimensions and the degrees of freedom left. A set drives the shape through the sketch solver, as typing in the box does, and answers with the same read-back; a value that would over-define the sketch is kept driven and the answer says so. `slicerx_design_sketch` constraints also take the X axis, as a curve with loop -1 and segment 0, to measure a line's angle from. `slicerx-mcp call` runs both from a shell.
- `slicerx_app_model_op_preview` reads the operation preview of the Model tool the person has open (push and pull, fillet and chamfer): its status (`none`, `pending`, `ok` or `error`), the error shown next to the tool, whether the view keeps the last good preview through that error, and whether the shown preview adds or removes material. `slicerx-mcp call` runs it from a shell.
- `slicerx_app_model_push` reads Push and pull as the person has it open in the app's Model, over the app link: whether it is open, the picked face (object, part, a point on it, its normal and the body's thickness behind it), the Distance box as typed, the distance it reads as and the operation it makes (`pull`, `cut` or `through`, with the chip's words). `slicerx_app_model_push_set` types a distance into that box for the person to apply with Enter; nothing changes in the project until they do. `slicerx-mcp call` runs both from a shell.
- The rest of the model ring's object verbs for clients: `slicerx_project_lock` locks or unlocks an object (move, rotate, scale, lay on face, center, cut and move to plate refuse a locked one, and an arrange leaves it on its plate), `slicerx_project_printable` leaves one out of the print where it sits, `slicerx_project_center` centers one on the bed, and `slicerx_project_split_objects` and `slicerx_project_split_parts` split its separate bodies to objects or parts. `slicerx_project_show` reads back `locked` and `printable`, and `slicerx-mcp call` runs them from a shell.
- Open-project named values and expression bindings: `slicerx_app_values`, `slicerx_app_value_set`, `slicerx_app_value_remove` and `slicerx_app_step_bind`, also available through `slicerx-mcp call`. Replies include resolved values, errors, bindings and pending updates on other plates. Failed edits retain their resulting state in `error.details`.
- `slicerx_app_history`, `slicerx_app_undo` and `slicerx_app_redo` expose the open project's toolbar history, with revision checks and resulting plate, object, settings and timeline read-back. The same commands run through `slicerx-mcp call`.

- `slicerx_geom_hole` makes a round hole another size, as the app's hole tool does: a new diameter, a blind hole's depth, and a counterbore or a countersink at its entry. Pick the hole by a point on its wall (`face`) or by `center` and `axis`, a point on its axis line and the axis. It answers with the hole as found before the change and as made after it (`center`, `axis`, `diameterMm`, `depthMm`, `kind` through or blind, `head`); a pick that finds no hole says what face is there. On a design it adds the same `hole.apply` step the hole tool records, so the step replays and edits like one made by hand, and it runs in the open app over the app link like the other design tools. `slicerx-mcp call geom_hole` runs it from a shell.
- The model ring's verbs for clients: `slicerx_project_duplicate` copies an object as new objects of their own (same model, rotation, scale, settings and volumes), `slicerx_project_rename` renames one, and `slicerx_project_lay_on_face` lays one on the face whose outward normal `slicerx_geom_faces` gives. Each answers with the project, so a client reads the change back.
- `slicerx_mimir_cloud_status` reads mimir cloud's status from the open app over the app link: whether the build offers it (`cloud`), whether mimir runs on it (`enabled`), `signed_in`, `needs_sign_in`, and today's use and what is left (`quota`, in US dollars, only while mimir runs on mimir cloud) or why it could not be read (`quota_error`). It never carries a key or a token. `slicerx-mcp --mimir-cloud-status` prints the same object as one JSON line, or `{"error": {"code", "message"}}` with exit code 1.
- `slicerx_mimir_tab` reads what answers in the mimir tab of the open app over the app link: `link` is `model` when a model is set up (with its `provider` and `model`, and `auto` naming the small model it starts on and the larger one it moves to for a picture, a PDF or a part of many steps), `scripted` when no model is set up, or `none` before the tab opens; `tools` lists the tools mimir has there. It never carries a key or a token.
- Slices report which filament each object's features printed with. `slicerx_slice` gives `featureFilaments` per plate and `slicerx_slice_file` gives `feature_filaments`: for each object, the filament slots its walls, infill, surfaces, support and other features printed with, after the project's and the object's own settings (sx engine). `slicerx-mcp call` reads it from a shell.
- `slicerx_design_sketch` takes `constraints` on its loops, dimensions among them: points by loop, place and segment (the sketch origin is loop -1), lines and circles by loop and segment. The app solves the sketch first, as its dimension tool does, so the loops move to meet them, and a dimension that would over-define the sketch is kept driven. The answer gives the degrees of freedom left and which dimensions are driven; constraints that conflict are refused and nothing is added.
- `slicerx_geom_sketch_edit` edits sketch loops as the sketch tools do: `intersect` lists where segments cross, `trim` takes a piece back to the nearest crossings and joins what is left to open chains its ends meet, `extend` runs an open end on to the next curve, `mirror` adds copies across a line and `pattern` adds copies along a step or round a center. It answers with the loops and, for each, the loop it came from.
- `slicerx_geom_sketch_solve` solves a constrained 2D sketch: points, lines, circles and arcs held by coincident, horizontal, vertical, parallel, perpendicular, tangent, equal, symmetric, distance, angle and the other sketch constraints. It answers with the solved points and radii, the degrees of freedom left, which points can still move, and the constraints that conflict or repeat.
- `slicerx_mimir_quota` reads today's free mimir use on this computer from the app over the app link: what the install and the network have used of their daily caps, in US dollars, and whether mimir cloud is open. `slicerx-mcp call slicerx_mimir_quota` reads it from a shell.
- `slicerx_printer_status` and `slicerx_printer_list` show what a printer reports wrong now (an HMS code or a print error) through sx-link: the first problem in the summary, a `problem` row with its code in the display, and `issues` in the output. Problems left over from an earlier job are left out.
- Project filaments: `slicerx_project_add_filament` adds a filament after the last one and `slicerx_project_set_filament` changes one's material type or color, as a person does on the app's filament rail. Both answer with the project, and `slicerx_project_show` lists its `filaments`. Once a client sets one, the project's slices carry `filament_type` and `filament_colour` for every filament.
- `slicerx-mcp call <tool> [<json>] ...` runs tools from a shell, in order in one process, and prints one JSON line per call; it stops with exit code 1 at the first failure.
- `slicerx_project_add_model` takes `bodies` for an STL that holds several separate bodies: `auto` (the default, one object as before), `parts` (one object with a part per body) or `objects` (an object per body). The answer lists each new object with its part count (`objects`, `object_count`, `part_count`), and `slicerx_project_show` gives every object's `parts`.

- `slicerx_printer_history` reads a printer's past jobs through sx-link, newest first: file name, result, start and end time, duration and filament used, as the printer keeps them. Read only; `limit` takes 1 to 200 (default 20). On simulated printers it says the history comes through sx-link.

- Placement and per-object control of the open project: `slicerx_project_move`, `slicerx_project_rotate`, `slicerx_project_scale`, `slicerx_project_plate_add`, `slicerx_project_plate_remove`, `slicerx_project_move_to_plate`, `slicerx_project_remove_object`, `slicerx_project_object_settings`, `slicerx_project_add_volume` (negative, support blocker, support enforcer or settings modifier, as a box, cylinder or STL), `slicerx_project_remove_volume` and `slicerx_project_height_ranges`. Each answers with the project after the change; `slicerx_project_show` now lists each object's rotation, scale, place, settings, volumes and model bounds, where every copy sits on its plate, and the height ranges. The sx engine slices with all of them.
- `slicerx_open_in_app` opens a model or project in the SlicerX desktop app on this computer, as the browser's Open in SlicerX button does.
- The checks and project operations the SlicerX app runs from its panels are tools now, so a client can do what a person does there: `slicerx_gcode_inspect`, `slicerx_risk_report`, `slicerx_energy_estimate`, `slicerx_fit_check`, `slicerx_mesh_analyze`, `slicerx_printer_config_check`, `slicerx_spool_fit`, `slicerx_overnight_readiness`, `slicerx_spool_inventory`, `slicerx_printer_match`, `slicerx_fleet_overview` and `slicerx_ams_mapping` read; `slicerx_supports`, `slicerx_orientation_search`, `slicerx_mesh_repair`, `slicerx_hollow`, `slicerx_emboss`, `slicerx_scale_with_tolerance`, `slicerx_threads_and_fits`, `slicerx_smart_layer`, `slicerx_multicolor_assign` and `slicerx_region_modifiers` change the open project (class slice). The checks read the plates `slicerx_slice` sliced; the mesh tools need `sx-geom`. None of them starts a print.

- Slice and estimate results carry `notices`, warnings with a code. `no_printer` says the slice named no printer, so the engine used its generic machine ("No printer chosen, so this slice used a generic 200 mm machine; times and limits are not for your printer."). The same line is in `warnings`.

- Set up local AI: `slicerx_local_ai_check` (hardware, one recommended model with its reason, size and license, running Ollama or LM Studio), `slicerx_local_ai_status` (installed local models and the one set up last) and `slicerx_local_ai_setup` (an Ollama download with progress notifications, then a tool call and speed check). Setup always asks the user first. Requests go only to 127.0.0.1. An edition config turns them off (`features.localAi`) or limits the models (`ai.allowedLocalModels`).
- A tool that must ask for a particular call (`mustAsk`) now asks over MCP even when its class is set to Allow, as it does in the app.

### Changed

- `slicerx_design_open` reads 3MF files with the engine's 3MF reader (sx-geom `format.read3mf`), the one the app uses, instead of a reader of its own. Parts keep their shared vertices, and a file in centimeters, meters or inches now places its build items in millimeters too. `readDesigns` takes the engine as its first argument and returns a promise.
- The `project_gcode_review` message is one short line and what to do ("edited.3mf's printer G-code doesn't match the Bambu Lab A1 profile's. ..."). The per-script counts and flagged lines stay in `details`, which adds `summary` (that first line) and `printer` (the printer it was compared with), so a client can show one line and keep the rest behind a toggle.
- A project with its own printer G-code and no printer to compare it with (no `machine:` profile, and a printer SlicerX has no profile for) is refused with the new code `printer_needed` instead of a diff against the generic machine's G-code, where nearly every line read as added. `project_gcode: "profile"` slices it as before.
- A project object whose mesh a tool replaced (cut parts, a repaired or hollowed mesh) keeps its geometry and rotation, so it slices; before, the plate came out without it.
- Project meshes are handed to the mesh tools with shared corners, so a closed STL measures watertight instead of showing every edge open.
- License: the server code is Apache-2.0. The bundle inlines the AGPL-3.0-or-later stock profiles, so the package is `Apache-2.0 AND AGPL-3.0-or-later`, with the AGPL text in `dist/LICENSE-AGPL-profiles.txt`.
- The published `./agents` entry is built (`dist/agents.js`), and both entries ship self-contained type declarations.
- Starting, resuming or sending G-code to a printer can no longer be approved through MCP. Those requests return `needs_person` and wait for a person in SlicerX or on the phone; `slicerx_approve` can only decline them. Pause and cancel still follow the policy. `slicerx_approve` ignores `bed_clear`.
- HTTP mode requires a bearer token on every request, loopback included. A new token is written to a 0600 file at every launch, or set with `SLICERX_MCP_TOKEN`. `--token` is refused, since command lines are visible to other users.
- In link mode a person-only request is registered with its work (`approvals.register {request, work}`), and the hub's `approval.done` report shows in `slicerx_pending_approvals`.
- HTTP mode uses MCP sessions, each with its own pending approvals, so a session can list and approve only its own requests.

### Fixed

- Windows command-line and MCP clients can read the remembered hub credential saved by the desktop app. App grants still control reads and edits; test editions use their own credential name.

- A call the server refuses before the tool runs (a tool it doesn't have, or arguments the tool's input schema rejects) reads plainly, over stdio and HTTP: "Tool slicerx_x not found" instead of "MCP error -32602: Tool slicerx_x not found". It is still a tool result with `isError`, and requests the protocol refuses are still JSON-RPC errors with their codes.
- `slicerx-mcp --printers link` as a stdio server now exits when the client closes stdin, after answering the requests it had already read. Before, its sx-link connection kept it running until something stopped it. With no printers or `--printers demo` it already exited.
- `slicerx-mcp --printers link call ...` now exits once its calls are done: 0 when every call worked, 1 when one failed. Before, it printed the results and then kept running with its sx-link connection open until something stopped it.
- `slicerx_region_modifiers` with `apply` now changes the open project: it adds a ring round each named hole and each named box, cylinder or sphere region as modifier volumes, and puts the feature-only settings on the object, as the app does. Before, over MCP it only returned the plan with "This project cannot hold volumes or object settings here, so nothing was applied." `slicerx_project_show` lists what it placed.
- `slicerx_printer_queue` sends a Bambu Lab printer the plate as a `.gcode.3mf` with a slot map, as the app's Print sheet does. Before, the plate went as plain G-code with no `ams_mapping`, and a P1S with an AMS stalled at the start. Without `slotMap`, each filament is fed from the loaded slot of its material and closest color, read from a fresh status. The call is refused before any card when a filament has no loaded slot of its material (`no_matching_slot`), when the printer has not reported its slots yet (`slots_not_reported`), or when two filaments would share a slot (`duplicate_slot`). The `needs_person` answer carries the `file` and `slot_map` handed to the hub, and a started print's result carries `slotMap` and `slotMapSource`.
- A slice or estimate that names no process now takes its supports from the printer, as a fresh plate in the app does: the maker's own Standard preset for the printer and nozzle where SlicerX ships one (off on Bambu Lab printers, with the preset's support style), and SlicerX's Standard tier's tree supports for no printer or a printer with no maker preset. Before, `process:slicerx-default` turned tree supports on for every printer. That profile no longer sets any support keys; a process profile, an Easy goal, a process preset file or an `enable_support` override still turns supports on.
- A Bambu Studio 2.8 project's `reduce_infill_retraction_mode` now reaches the engine as `reduce_infill_retraction`. It was dropped as a key only Bambu Studio has, so every travel inside the infill retracted. "Enabled" skips those retractions, "Disabled" keeps them, and "Auto" skips them when every filament's `filament_metal_stickiness` is low or untested (PLA) and keeps them otherwise (PETG). A file with only the old `reduce_infill_retraction` key reads as before. The app opens projects the same way.
- A travel through a printer's exclusion area or the A1's nozzle wrap check corner, or within the nozzle's width of one, is now refused with `collision` like a print path there, as a `keep_out` item in `details.collisions`. The server reads sx's sentence for it ("A print path or travel enters ...") as well as the older one.
- A Bambu Studio or OrcaSlicer project sliced with `project_settings` no longer fails on its stock start G-code (the Bambu Lab A1's `M211`, `M500` and `M18`). The project's printer G-code is compared with the printer's stock text, the template SlicerX ships or any version Bambu Studio or OrcaSlicer shipped for the model, and stock text is used as it is; the result's `project_gcode` says which. Other G-code stops the call with the new `project_gcode_review` code, with the diff against the printer profile's G-code and each flagged line in `structuredContent.error.details`. The new `project_gcode: "profile"` argument slices with the printer profile's G-code instead. No tool call can choose the project's own G-code.
- `slicerx_slice_file` and `slicerx_estimate_file` slice a 3MF plate as its objects, so `print_sequence` "by object" prints each one before the next, with the nozzle lifted over the finished ones. Before, the plate became one mesh and printed layer by layer. A file is placed on the printer's own bed (`printable_area`), `project_settings` takes a plate's own print sequence, and `slicerx_inspect_project` lists it per plate. A by-object plate whose objects sit too close for the toolhead, or with an object the gantry or lid would hit, fails with the new `sequence_clearance` code.
- A user's preset that inherits from a maker profile SlicerX ships (`profile_files`, or a slot in `filaments`) no longer makes the whole slice use the strict G-code checks. G-code it inherits is the shipped text; only G-code the file sets itself is checked strictly. Before, a user's PLA preset on a Bambu Lab A1 stopped the slice with `preflight_blocked`.
- `slicerx_slice_file` and `slicerx_estimate_file` no longer refuse the start G-code of shipped printer profiles (the Bambu Lab A1's, for one). Like the app, they mark the custom G-code as trusted only when no G-code setting came from a profile SlicerX does not ship, a project file, a preset file or an override; anything else still gets the strict checks. Projects sliced through mimir (`slicerx_slice`) follow the same rule.

### Added

- The integrator kit as resources: `slicerx://docs/integrators/agents` (the guide for coding agents) and `slicerx://docs/integrators/quickstart`.
- `filaments` on `slicerx_slice_file` and `slicerx_estimate_file`: a filament profile, preset file or spool color per slot, each setting only its own slot. The `.gcode.3mf` then names the right type and color for every slot.
- A `./cli` entry, so an app finds the server with `require.resolve('@slicerx/mcp/cli')` or `import.meta.resolve`.

- For apps that build SlicerX in: `slicerx_slice_file` and `slicerx_estimate_file` take 3MF and `.sx3mf` projects with a `plate`, the project's own settings (`project_settings`), and the user's OrcaSlicer and Bambu Studio presets and preset bundles (`profile_files`). Results list filament use per slot, tool changes, the plate and the G-code's SHA-256. `output: "gcode.3mf"` writes a `.gcode.3mf` for Bambu Lab printers, with the plate picture the engine draws, and `preview: true` the SXPV preview. Both tools send progress notifications.
- `slicerx_inspect_project`: plates, saved presets, filament slots and settings of a 3MF or `.sx3mf` project.
- `slicerx_list_profiles` lists the makers' filament presets (`stock-filament:` ids) and filters by `source`.
- Stable error codes on every refused call: `Error: <code>: <message>` and `structuredContent.error`.
- Locked projects: `slicerx_sxlock_inspect`, `slicerx_sxlock_open` and `slicerx_sxlock_export`, acting for the account whose API token the server holds, within its `sxlock_open` and `sxlock_seal` scopes. Off until the edition's account service is configured.
- Cloud slicing tools `slicerx_cloud_slice` and `slicerx_cloud_jobs` against the SlicerX cloud API. Off unless `--cloud-api`, `SLICERX_CLOUD_API_URL` or an edition config with `cloudSlicing` names one; until then both answer that cloud slicing is not configured and make no network call. Jobs never name a printer. Submitting checks `GET /v1/access` first, the invite, upload and daily job limits come back as plain errors, and results say that links expire after 7 days.
